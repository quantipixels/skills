Where the agent workflow broke down

A visual map of the issues found across session analysis, implementation, skill design, configuration, project delivery, and reporting, with a correction map for where each remedy belongs. The central finding is not weak coding intent. It is a control system that often depended on the user to restore scope, evidence, and acceptance.

Executive verdict

Correct work became expensive because control arrived late

The recurring mechanisms were mixed contracts, incomplete coverage, phase ambiguity, and completion before the real acceptance boundary. Proof expansion was usually a downstream recovery cost, not the first failure.

Central visual

The dominant failure chain

Five stages explain why a reasonable task could turn into a long, difficult session.

1. First divergenceContract drift

The outcome, owner, repository, phase, or authority changed without a clear reset.

2. Blind spotCoverage gaps

Projects, decisions, failure paths, or required evidence disappeared from the working view.

3. False closePremature completion

Implementation or focused tests passed before the real user or operational path passed.

4. Recovery costProof expansion

More agents, repeated reads, new checks, and corrective rounds attempted to recover confidence.

5. Residual riskState drift

Reports, installed skills, branches, deferrals, and published state no longer described one candidate.

Accessible summary: material contract changes were the common upstream cause. Missing coverage and weak acceptance gates followed. Recovery then produced more orchestration and left records vulnerable to drift.

Correction architecture

Put each remedy at the narrowest effective layer

The premise is only partly accepted. The failures justify stronger recovery gates and several owner-skill fixes. They do not yet justify one broad skill that duplicates routing, delivery, continuity, retrospective analysis, and handoff.

Layer 1

Global instruction

Use for an invariant that must hold across tasks, repositories, and skills, such as contract recovery, stale deferrals, or configuration proof.

Layer 2

Project instruction

Use for a local acceptance path or operating boundary, such as Funpa packaging or EVHACS live API behaviour.

Layer 3

Existing skill fix

Use when the missing behaviour is already part of a declared owner's outcome. Ayewo, Alaga, Ko Skill, HTML Artifact, and Olofofo remain the relevant owners.

Layer 4

Conditional new skill

Use only for a recurring independent outcome with no adequate owner. Active course correction is a candidate, not an approved new skill.

Decision: trial one compact global recovery and completion gate in two independent material sessions. Create a new skill only if either session still needs multi-step recovery that cannot fit one transition receipt.

Composite wording

Use compact gates instead of scattered reminders

These are candidate blocks. They reduce duplication by grouping related checks at the point where they matter.

Global recovery and completion gate

For ~/.codex/AGENTS.md

When work materially diverges from the last confirmed outcome, or before claiming completion, reconcile the active outcome, owner, repository and candidate, mutation authority, requested coverage, minimum real acceptance path, retained decisions, durable records, and unresolved evidence gaps. Classify current work and proof as retained, stale, out of scope, or unknown. Continue only from the reconciled state. Use handoff when the owner or execution context changes.

Limiter

For a small bounded task with no material transition, use one sentence of readback rather than a recovery record.

Artifact durability and freshness

For HTML Artifact and Olofofo

Before creating a report or durable record, classify its lifecycle as snapshot or living and its retention as temporary or durable. Do not describe ignored, untracked, temporary, or local-only storage as durable. When its source candidate changes, mark dependent facts, comparisons, recommendations, and dispositions stale until refreshed or labelled historical.

Placement

Lifecycle and retention in HTML Artifact; candidate freshness in report patterns; archival handoff in Olofofo.

Delivery acceptance

For Alaga

Before delivery, name the complete job, execution horizon, minimum real acceptance path, and proof that can detect its highest-risk failure. Before closure, confirm that every in-scope unit maps to the current candidate, required documentation is reconciled, blocking findings are closed, and no focused test is being used as a substitute for another boundary.

Change style

Compress existing Alaga rules into this gate. Do not add a second overlapping procedure.

Project-specific acceptance template

For project AGENTS.md files

For <project outcome>, acceptance requires <real path>. Keep <phase A>, <phase B>, and <phase C> as separate states. A change to <critical boundary> reopens <affected proof>. Do not combine <unrelated workflow> with this delivery contract.

Implementation and configuration

Concrete defects found

These were bounded defects or incidents. They are not all repeated corpus patterns.

Implementation defects and expected behaviour

Brand shell construction

A filename was placed into a shell command, creating an injection path.

Desired

Return executable plus argument array. Never rebuild a shell string.

Standalone slide tokens

Project CSS could hide a missing embedded token, and dark-theme overrides were omitted.

Desired

Validate against embedded tokens only and include applicable theme blocks.

Provider timeout state

A timed-out write could have succeeded remotely while appearing failed locally.

Desired

Treat it as unknown state, read the exact target, then decide whether to retry.

Provider host trust

Installed provider code could predate custom-host trust and credential-isolation rules.

Desired

Normalize and trust the host, isolate credentials, refresh identity and head, and read writes back.

Test module collisions

Several Python suites used the generic module name core, so one aggregate process could collide.

Desired

Run isolated suites or use package-qualified module names.

Generated test caches

Ignored __pycache__ directories returned after cleanup.

Desired

Remove only generated state with confirmed provenance.

Configuration weaknesses and expected behaviour

Inactive network enforcement

Allowlist configuration existed without the proxy required to enforce it.

Desired

Enable enforcement and prove one allowed and one denied request.

Broad trust

Trust covered large personal and temporary filesystem surfaces.

Desired

Trust exact repositories only.

Dead or broad hooks

Some hook registrations were inert, risky, or wider than their useful outcome.

Desired

Keep only bounded hooks with a current purpose and proven trigger.

Stale settings

Unsupported or obsolete fields remained in configuration.

Desired

Remove stale fields and perform a strict configuration load.

Concurrency ambiguity

The active-thread cap was confused with a cumulative delegation budget.

Desired

Keep active concurrency separate from total delegation and proof spend.
