## Retained depth and deliberate omissions

The direct engineering methods keep behavior/consumer tracing, semantic reuse, selective TDD, independent review, domain identity, stateful proof, framework invocation, tenant boundaries, numeric units, property testing, migrations and build invalidation. They are organized into cohesive conditional references rather than dozens of workflow stages.

The existing module-design reference, Yorùbá specialist, system cleanup and optional Codex execution profile remain because they own useful independent methods. Their retention does not prove superior model outcomes. The model roster stays confined to the optional profile; the portable core does not choose models.

The generic lifecycle/state registries, default playbook progression, reusable HTML control assets, separate language/style reference taxonomy and professional-stance experiment bookkeeping are intentionally not reproduced. Ordinary reports need neither these mechanisms nor a proof campaign. The history links preserve earlier design and experiment provenance.

## Host behavior

`qp-update` and `pese` declare Claude's `disable-model-invocation: true` and Codex's `policy.allow_implicit_invocation: false`. These declarations preserve supported explicit invocation and suppress automatic selection according to the host contract. They are not a security sandbox or authorization mechanism. Direct instructions still delimit permitted effects.

Sources: [Codex skills](https://developers.openai.com/codex/skills/) and [Claude skills](https://code.claude.com/docs/en/skills). Compatibility must be checked against the installed host version. Verify incidental mention, explicit command, actual file loading and scoped behavior separately. The package check verifies metadata consistency only. No fresh native installation/invocation or model comparison was performed by the rebuild author.

No user configuration, permissions, services or installed skills are modified by this source PR. The existing plugin identities and release mechanism remain. The changeset marks a major version; publishing and merging are not part of the rebuild.

## Proof migration and recovery

Seven existing fixture groups and the standalone oracle are retained byte-for-byte under `proof/`. Java domain-value and Python reuse rejection controls remain directly runnable. Historical full campaigns, observations, scenarios and patches are reachable through the immutable [evidence index](evidence.md). Private raw traces may not be available; history is not a substitute for those missing artifacts.

Campaign-level integrity manifests, frozen profile generation and result aggregation are intentionally removed. For comparisons, the experiment owner must pin candidates and preserve independent judging inputs using native host boundaries. A directory is not isolation. Direct oracle invocation is only appropriate for trusted candidate code in a disposable environment; it is not a hardened runner for untrusted code.

Before adopting the new instructions widely, exercise the selected [behavior tasks](../proof/tasks.md), including folded decision and HTML paths, with actual supported hosts. These tasks are unrun acceptance protocols, not claimed passes or a hidden release certification.

Recover source by reverting the rebuild or restoring the baseline through the existing manager, then reload and verify the active installation. That restores source behavior only; it cannot undo actions already performed by an agent, reconstruct private traces or automatically remove manually copied files.
