# Adopt adaptive Akọ̀wé implementation counsel

Status: Accepted

## Context

The catalogue-backed `akowe-code` experiment reduced public skill proliferation but still made one companion carry a private Java, Spring, Kotlin, Ktor, Elixir, and Phoenix expertise corpus. That made freshness, coverage, and maintenance depend on embedded references while the host may already expose exact repository evidence, relevant specialist skills, and current owning sources.

The useful independent outcome is not possession of a code catalogue. It is synthesising the smallest current expertise that can materially improve one active implementation without taking over delivery, architecture, simplification, or review.

The intermediate `akowe-code` identifier was not released. A shorter identifier better reflects a general expert companion rather than a language-specific catalogue.

## Decision

1. Publish the Experimental companion as `akowe`, displayed as Akọ̀wé.
2. Remove its embedded language/framework, general-craft, known-bad, complexity, source-map, and catalogue-maintenance references.
3. Derive expertise needs from the exact candidate and credible failure paths, then discover the smallest relevant skills from current host descriptions and invocation metadata.
4. Consume every selected skill's native result without copying its procedure or maintaining a fixed specialist map.
5. Research only material gaps against current owning primary sources. Use `iwadi` when research is independently substantial or durable and `ro-wo` when the gap is a consequential premise.
6. Maintain exact-current Expert Implementation Counsel and return deltas only when the candidate, mechanism, contract, or controlling evidence changes.
7. Apply a proportionality gate to proposed abstractions, dependencies, state, queues, caches, patterns, and proof. `No material expert intervention` remains valid.
8. Keep Akọ̀wé explicit-only and advisory. Stable implementation, architecture, project-knowledge, tool, simplification, and review owners remain complete without it.
9. Runtime findings do not automatically become project or shared guidance. Durable learning remains with its existing owner and authority boundary.

## Consequences

Akọ̀wé can apply to any stack the host can evidence without requiring a QP-maintained ecosystem pack. Missing specialist coverage becomes a visible research or evidence gap instead of guessed expertise.

The runtime package becomes substantially smaller. The former catalogue research remains historical evidence outside the skill package, and the earlier consolidation ADR is superseded rather than rewritten as though the intermediate experiment never existed.

Dynamic skill discovery and current research can cost more than reading cached guidance, so Akọ̀wé must select only expertise capable of changing the implementation and stop when further evidence cannot change its counsel.

## Rejected alternatives

- Keep `akowe-code`: rejected because the unreleased suffix describes the former catalogue implementation more than the companion's general outcome.
- Retain embedded references as a fallback: rejected because that preserves the stale private-expertise centre of gravity.
- Move the catalogue into another hidden skill: rejected because it reproduces the same ownership problem.
- Put adaptive counsel directly inside Alága: rejected because the result is independently useful and must remain optional rather than making stable delivery depend on an experiment.
- Automatically promote task findings into shared guidance: rejected for provenance, authority, privacy, and drift risk.
