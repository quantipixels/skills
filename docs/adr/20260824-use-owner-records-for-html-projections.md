# Keep source meaning separate from HTML projections

Status: Accepted for semantic authority; mandatory records and continuously maintained initiative views superseded by the greenfield composition decision on 2026-09-07. Workspace topology is governed by [the Git-common workspace decision](20260903-worktree-independent-qp-workspace.md).

## Current decision

An HTML artifact projects supplied material or an existing authoritative result. Rendering must not create or revise domain meaning, decisions, status, confidence, readiness, or evidence. If a view and its source disagree, the source controls and the view must disclose its gap or staleness.

A separate Markdown owner record is not required merely because HTML is produced or several skills contribute. Use conversation context for one-session work and an existing project destination for maintained knowledge. Create a durable record only when continuity, recovery, review, or another real consumer needs one. Shared `.qp` storage is optional; when selected, Akọsílẹ̀ supplies its paths and safe-publication mechanics without owning semantic content.

Maintain a browser view when the user or governing workflow requires it, or when it materially improves the reader's judgment. Initiative size and lifecycle transitions alone do not impose a view. Update the semantic source first and refresh an existing view when the changed meaning affects its use. Required human-critical meaning must be visible with provenance; linking omitted decision-changing information is insufficient.

HTML Artifact owns representation, accessibility, source mapping, and proportional verification. Test the actual delivered surface when a browser-dependent claim needs proof; do not introduce automatic full-browser gates solely for first render, artifact size, or a plan-status change. The current skill is the execution contract.

## Why

Separating source meaning from presentation allows a failed or stale render to be repaired without losing the accepted result. Optional persistence and views avoid parallel records and routine regeneration when the conversation or existing project document is adequate. Skills can combine expertise without creating a receipt or handoff at every boundary.

The original dated paths, eager workspace initialization, fixed record envelope, and mandatory continuous Atọ́nà view are historical, not current instructions. Their rationale and rejected alternatives remain available in [the original decision](https://github.com/quantipixels/skills/blob/647c411d5c45ecb3fccc77a4eb38580e53c5df86/docs/adr/20260824-use-owner-records-for-html-projections.md). Stable subjects and lazy initialization remain governed by [the focused-kernel decision](20260828-keep-akosile-scripts-focused.md).
