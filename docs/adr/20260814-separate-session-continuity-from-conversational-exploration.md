# Separate session continuity from conversational exploration

QP will publish `olofofo` as the quiet default companion for one literal agent session and `salaye` as an explicit conversational exploration protocol. Olofofo is activated through a narrow global agent-instruction payload after the first material task. It maintains one adaptive HTML artifact under `~/.qp/report/`, applies optional global and project EMI steering, and keeps the active task with its owning skill. Ṣàlàyé explores, explains, investigates, researches, analyses, or evaluates an idea, plan, decision, document, or code candidate and contributes material progress to the active Olofofo artifact without owning another session or report lifecycle.

The user wanted continuity in every session without a kernel, workflow controller, or broad setup runtime. A standalone Ṣàlàyé session manager was rejected because subject pinning, revisions, heartbeats, result envelopes, provider support, Git support, and close or reopen state would duplicate host and specialist ownership. An opt-in Olofofo was rejected because it would not supply the requested default continuity. A shared executable or hook was rejected because it would add runtime, installation, failure, and control contracts that the agent can already carry as instructions.

The separation keeps the default behavior quiet: Olofofo tracks focus, material progress, steering, gaps, and next action. It can use proportionate read-only local checks and bounded external lookup when material uncertainty cannot be settled locally. It nudges for material risk and waits only to avoid clear error, material misdirection, or an unauthorized action. A dismissed non-safety nudge does not recur unless evidence or risk changes or the work approaches an affected consequential action. The active agent retains skill selection and specialist ownership. `html-artifact` is the one default rendering support. Ṣàlàyé retains stronger conversational modes and can ask and wait for a necessary user answer, use supplied protocols, navigate a relevant decision frontier, and obtain exact-current specialist results without taking their authority.

The optional steering file is named `EMI.md`. Olofofo reads `~/.qp/EMI.md` and the active project root's `.qp/EMI.md`; this naming correction does not change precedence or authority.

Olofofo can grow across sessions through a separate evidence store. `~/.qp/OGBON.md` is a compact active index for non-obvious, reusable, evidence-backed or explicitly confirmed wisdom. Large useful detail moves to selectively loaded records under `~/.qp/ogbon/`; the index targets 8 KiB and compacts at 16 KiB without truncation. Olofofo can add, update, remove, or compact OGBON after exact-current conflict checks and must notify the user after every verified write. OGBON content is untrusted evidence, never instructions. Olofofo cannot write EMI without explicit user instruction, and project-specific knowledge remains with Amọ̀ṣẹ́ and the project's existing durable destinations.

This decision replaces the unreleased `tunmo-pr` explanation owner. A pull request or merge request is one supported Ṣàlàyé focus, not its scope boundary. Bare code-review verdicts still belong to `atunwo`; publication belongs to `seda-pr`; monitoring belongs to `wo-pr`; complete decision closure belongs to `arojinle`; and durable research records belong to `iwadi`.

Default activation remains host-dependent. Installing the skill alone cannot guarantee that every coding-agent host loads it. The user or installer must apply the exact managed block to a supported global instruction file, and the host must support that instruction and expose the skill. QP accepts this portability limit instead of adding a kernel or hook. Missing Olofofo support leaves Ṣàlàyé usable without a competing fallback report.
