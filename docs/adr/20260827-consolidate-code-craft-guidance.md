# Consolidate code-craft guidance behind one Experimental companion

Status: Accepted

## Context

QP introduced Experimental `akowe-java` and `akowe-spring` catalogues as source-backed language/framework guidance. Before their first package release, the experiment showed that exposing each ecosystem as a public skill increases installation/routing/release surface while the user-visible outcome is usually one question: **what should expert code for this exact task and stack look like?**

The same review found adjacent quality-control gaps: Atọ́nà no longer made material decision-frontier closure explicit at its readiness gate; TDD could accumulate construction tests as permanent proof; complexity metrics lacked a semantic interpretation owner; and code review could ask for tests without proving an invariant-level evidence gap.

Repository policy already prefers one public skill only for an independent outcome and keeps Experimental skills isolated from stable-owner sufficiency.

## Decision

1. Retire the unreleased public runtime forms of `akowe-java` and `akowe-spring`.
2. Publish one explicit-only Experimental `akowe-code` that returns a bounded exact-candidate **Code Craft Brief**.
3. Keep Java, Kotlin, Elixir, Spring, Ktor, and Phoenix guidance as compact internal references selected by detected stack; unfamiliar/newer stacks use bounded primary-source research instead of another public skill.
4. Treat known-bad patterns as a candidate-triggered layer inside Akọ̀wé Code or, when reliably mechanical, a repository tool rule. Do not restore Èèwọ̀ as a separate public skill.
5. Runtime research never auto-mutates shared guidance. Recurrent cross-project findings go through retrospective + Kọ Skill; project-specific confirmed patterns may use an authorized Amọ̀ṣẹ́ `local-craft` owner record.
6. Restore Atọ́nà's explicit material Decision Frontier Gate and require it to be empty before `Planned`; Àròjinlẹ̀ resolves only unresolved consequential user branches and does not reopen settled decisions.
7. Solution Architect retains architecture ownership and adds a compact Architecture Contract, native-platform/complexity/negative-architecture/fitness passes, and structured material-user decision gaps.
8. Alága owns mandatory proof compaction after TDD: construction proof is classified `KEEP | MERGE | DELETE | MOVE_TO_STRONGER_OWNER` by invariant before final review.
9. Parẹ́ remains read-only and owns semantic complexity/state-space/test-portfolio simplification; complexity metrics are investigation triggers, never automatic refactor thresholds.
10. Àtúnwò recommends new/changed proof only after identifying the invariant, current proof owner, escaping regression, cheapest stable seam, and why current proof is insufficient.
11. Irinṣẹ́ supplies deterministic metric/static/tool evidence without maintainability or defect verdicts.
12. Àyẹ̀wò routes repeated waste to the earliest prevention owner; stable owners never depend on Akọ̀wé Code.

## Consequences

The public Experimental surface becomes smaller while supporting more ecosystems. Akọ̀wé Code can operate open-world through bounded research but must remain context-bounded and stop after one brief. Stable workflows become stricter about decision closure, proof economy, and semantic complexity without gaining new public skills.

The dated Java/Spring research documents remain historical source evidence. Their detailed runtime rule files are removed with their public skill packages.

## Rejected alternatives

- Keep one public skill per language/framework: rejected for routing/install/release proliferation.
- Pure real-time research: rejected for latency, inconsistency, opinion mining, and research loops.
- Move all 195 Java/Spring rules unchanged under Akọ̀wé Code: rejected as the same encyclopaedia behind one wrapper.
- Put code-craft resolution directly inside Alága: rejected because a craft brief is independently useful for implementation or review support and should not absorb delivery authority.
- New public complexity/test/Èèwọ̀ skills: rejected because existing owners can express those recurring methods cleanly.
- Automatic self-learning from runtime sessions: rejected for authority, provenance, privacy, and drift risk.
