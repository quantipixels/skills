# Validate agent skills proportionately on demand

QP does not keep prompt eval suites or add behavioral test cases to this skills repository. Before eval removal, each unique current expectation moves into its owning skill; redundant or obsolete expectations are recorded in the delivery record.

Every skill change gets direct checks for its affected structural and integration surfaces. Fresh no-context subagent sessions are used only when material behavioral uncertainty remains. `ko-skill` selects the smallest realistic scenario set that can distinguish success from failure. It does not require one session per theoretical branch or an independent reviewer when direct evidence is sufficient. Provider writes, credentials, and repository mutation stay denied unless a disposable scenario explicitly authorizes them.

The minimum proof is defined before editing. If validation scope grows materially, work stops for a simplify, defer, or continue decision. Candidate changes invalidate only affected behavioral proof. Full prompts, outputs, environment details, and limitations stay outside repository source; an owning plan or delivery report keeps only the concise result when one exists.

This approach keeps validation independent where judgment matters without turning skill maintenance into a second delivery project. It accepts less uniform behavioral proof in exchange for evidence selected by risk and direct verification of deterministic surfaces.
