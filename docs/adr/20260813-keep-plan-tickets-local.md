# Keep plan tickets local

QP will add `seda-ticket` as the reusable owner for a checked local ticket graph derived from stable plan phases and review candidates. Atona retains plan identity, decisions, readiness, delivery milestones, integration acceptance, and closure. Alaga retains internal feature tasks, TDD slices, proof, and delivery procedure.

For ticket-backed delivery, `seda-ticket` creates or reconciles stable plan-scoped IDs, phase parents, candidate children, explicit dependencies, cycle checks, stale markers, durable replacement lineage, and optional Git evidence already supplied by a delivery owner. Atona supplies one stable graph ID, node-ID prefix, anchored phase and candidate definition keys, and predecessor mappings. Occurrence keys control node-ID preservation across continuous graph-node lifetimes; later reintroduction creates a new occurrence. For an Atona HTML plan, `html-artifact` owns the artifact, graph-only `<div id="local-ticket-graph">` boundary, and physical checked update. It uses a host-provided conditional atomic primitive or reports a capability gap; QP does not define a shared filesystem transaction runtime. `seda-ticket` prepares the derived-graph contents and verifies the returned exact artifact. Atona verifies the graph before it marks the plan `Planned`.

The first release is fully local. It has no provider adapter, remote identity, authentication, pagination, external read, or external write. A later provider projection requires a new architecture decision. The ticket workflow also defines no Git operation; it may only retain exact-current Git evidence produced by an owning delivery workflow.

This separates reusable local ticket-graph policy from Atona without creating a second ledger or moving plan or artifact authority. Every node stores one stable graph ID, a canonical anchored definition reference, a definition key, a node-occurrence key, graph relations, and graph lifecycle. Definition keys identify settled phases or candidates; occurrence keys identify graph-node lifetimes, including distinct parent occurrences across cardinality changes. Neither parent nor candidate nodes copy authoritative plan or delivery state. Candidate-to-candidate edges are the only dependency edges. The nodes bind to the source semantic plan revision; the resulting whole-artifact digest is returned separately. It accepts one additional skill handoff and the need to prove that `seda-ticket` is deep enough to justify a public owner. If stable identity, hierarchy, dependency validation, cycle detection, stale reconciliation, and checked local updates do not remain behind a small interface, the skill must not be published as a shallow pass-through.
