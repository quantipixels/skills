# Structural portfolio audit: assurance closeout

**Authority:** read-only structural portfolio judgment. This audit does not infer historical usage, selection frequency, incremental value, or promotion readiness.

**Scope:** the live hypotheses that can be resolved structurally before local-session analysis: `scope-guard`, `root-cause`, `pepeye`, the `ayewo-igba-ise` local-session adapter, and the profile/default-surface hypothesis. Adjacent owners were inspected only where they control those boundaries (`alaga`, `se-triage`, `atona`, `handoff`, `alarina`). This is not a claim that every portfolio member is optimal.

## Executive verdict

No structural evidence justifies a broad owner-count reduction or installation profile now. Scope Guard retains a distinct steering result. Root Cause and Pẹ̀pẹ̀yẹ remain credible independent Experimental owners whose promotion/fold decisions require real-use evidence. The local-session adapter earns its bundled-script boundary only as deterministic, privacy-preserving inventory/normalization; semantic selection/value judgment stays with Àyẹ̀wò.

New public-owner admission decisions are intentionally outside this structural closeout and keep Kọ Skill's separate boundary-proof gate.

## Findings

### S-01 — Scope Guard retains an independent stable result

**Disposition:** `KEEP`

`scope-guard` returns a standalone portable steering contract: exact outcome, task-local exclusions, expected change envelope, smallest proof, expansion gates, and deliberate ceilings. It explicitly does not implement, review, own architecture, or create lifecycle state.

`alaga` carries equivalent minimum-sufficient-mechanism and scope-expansion invariants inside delivery, but its native result is delivered software/build work. Folding Scope Guard into Alága would remove the directly selectable “constrain this task/agent without implementing it” result and conflate reusable steering with delivery authority.

**Revisit trigger:** real selection evidence that the public identity itself creates more routing harm than value.

### S-02 — Root Cause is structurally distinct from triage and correction delivery

**Disposition:** `KEEP_EXPERIMENTING`

The owner chain remains coherent:

```text
se-triage  → establish report validity/classification and next action
root-cause → establish the minimal causal mechanism/sufficient causal set
alaga      → deliver the software/build correction when diagnosis is settled
```

No braided lifecycle or duplicated mutation authority is structurally present. Structure therefore does not justify `FOLD` or `REMOVE`, but it cannot prove recurring public-selection value required for `PROMOTE`.

**Revisit trigger:** representative local-session opportunity/value/boundary evidence.

### S-03 — Pẹ̀pẹ̀yẹ has a credible supervision intent island

**Disposition:** `KEEP_EXPERIMENTING`

`pepeye` owns user-requested task-wide continuity across changing owners/candidates/proof states while refusing routing, planning, implementation, review, publication, or another lifecycle.

Its closest neighbours remain distinct:

- `alarina` selects/sequences owners when routing itself is needed;
- `atona` owns one initiative plan and progression lifecycle;
- `handoff` serializes current state for transfer to another session/agent.

No structural fold target preserves Pẹ̀pẹ̀yẹ's exact result without braiding authority/lifecycle. The unresolved question is whether users/agents benefit enough from selecting this public identity in real eligible work.

**Revisit trigger:** local-session evidence for eligible supervision opportunities, selected/missed cases, continuity benefit, and recurring cost.

### S-04 — Local session evidence script passes the bundled-script boundary conditionally

**Disposition:** `KEEP`

The `ayewo-igba-ise` session adapter owns only the mechanical seam that does not scale safely as repeated ad-hoc model work:

```text
local Codex/Claude JSONL stores + explicit filters
→ privacy-preserving session/root inventory + conservative structural references
```

It does not classify eligibility, skill value, mis-triggering, causal responsibility, portfolio disposition, or skill edits. References in host history are not promoted to semantic claims such as selected/loaded/routed unless the persisted evidence actually proves that stronger fact. Missing parent records remain unresolved rather than becoming artificial independent roots.

This is a deterministic machine-consumer boundary with recurring corpus-scale leverage; replacing it with ordinary prompt instructions would increase repeated parsing/privacy/schema-drift risk.

### S-05 — Profiles/default-surface reduction remains evidence-gated

**Disposition:** `DEFER`

No structural finding proves that simultaneous owner count is the binding selection problem. The portfolio already has direct-selection rules for obvious owners, a router for genuine ambiguity, an Experimental maturity distinction, and a separate A/B discovery experiment.

A reduced profile could improve common-case selection while hiding a legitimate independent result; structure alone cannot establish that trade-off.

**Revisit trigger:** discovery Arm A/B evidence, then Arm C only if residual visibility-count cost remains material.

## Healthy repetition retained

Some constraints intentionally appear in more than one owner because invocation boundaries differ. Scope/minimum-mechanism guidance in `scope-guard` and `alaga`, exact candidate/evidence boundaries across delivery/review/provider owners, and authority/trust rules in independently invokable provider skills are not duplication defects when each invocation must remain safe/correct on its own.

## Rejected actions

- Do not fold Scope Guard into Alága merely to reduce catalogue count.
- Do not fold Root Cause into triage or delivery from structural similarity.
- Do not fold Pẹ̀pẹ̀yẹ into routing/planning/handoff without real-use evidence that its supervision identity lacks value.
- Do not promote any Experimental owner from package structure alone.
- Do not create a default/core profile or target skill count from folder count.
- Do not expand the local-session adapter into telemetry, semantic analytics, or a routing classifier.

## Residual evidence gaps

- Experimental dispositions and stable-skill improvements require local real-use evidence where the decision depends on recurrence/value.
- The stacked-PR behavioral corpus still needs fresh-context execution.
- Discovery Arms A/B still need execution before profile work.
- `Validate` becoming required on `ori` remains repository administration rather than repository source.
- Host installation proof and model-visible behavioral proof remain distinct compatibility claims.

## Conclusion

The bounded structural hypotheses are exhausted: the suspected Scope Guard/Root Cause/Pẹ̀pẹ̀yẹ folds are not structurally justified, the local adapter remains a narrow deterministic seam, and further profile/promotion/fold decisions should wait for discriminating behavioral or real-use evidence rather than another architecture pass.
