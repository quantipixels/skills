## Findings

### S-01 — Scope Guard retains an independent stable result

**Disposition:** `KEEP`

`scope-guard` returns a standalone portable steering contract: exact outcome, task-local exclusions, expected change envelope, smallest proof, expansion gates, and deliberate ceilings. It explicitly does not implement, review, own architecture, or create lifecycle state.

`alaga` carries equivalent minimum-sufficient-mechanism and scope-expansion invariants *inside delivery*, but its native result is a delivered software/build job. Folding Scope Guard into Alága would remove the directly selectable “constrain this task/agent without implementing it” result and conflate reusable steering with delivery authority.

**Revisit trigger:** future selection evidence showing the public identity itself causes more harm than value.

### S-02 — Root Cause is structurally distinct from triage and correction delivery

**Disposition:** `KEEP_EXPERIMENTING`

```text
se-triage  → establish report validity/classification and next action
root-cause → establish the minimal causal mechanism/sufficient causal set
alaga      → deliver the software/build correction when diagnosis is settled
```

`se-triage` explicitly hands unresolved causal diagnosis to `root-cause`; `root-cause` excludes correction attempts; Alága consumes a settled diagnosis without owning causal investigation as a separate result.

No braided lifecycle or duplicated authority is structurally present. Structure does not justify `FOLD` or `REMOVE`, and cannot prove recurring public-selection value required for `PROMOTE`.

**Revisit trigger:** representative local-session opportunity/value/boundary evidence.

### S-03 — Pẹ̀pẹ̀yẹ has a credible supervision intent island

**Disposition:** `KEEP_EXPERIMENTING`

`pepeye` owns user-requested task-wide continuity across changing owners/candidates/proof states while refusing routing, planning, implementation, review, publication, or another lifecycle.

Its closest neighbours remain distinct:

- `alarina` selects/sequences owners when routing itself is needed;
- `atona` owns one initiative plan and progression lifecycle;
- `handoff` serializes current state for transfer to another session/agent;
- `pepeye` keeps an already-requested task coherent across those boundaries without taking their native results.

No structural fold target preserves that exact result without braiding authority/lifecycle.

**Revisit trigger:** local-session evidence for eligible supervision opportunities, selected/missed cases, continuity benefit, and recurring cost.

### S-04 — Yorùbá Glossary is an Experimental public-owner candidate, not yet admitted

**Disposition:** `INCUBATE_CANDIDATE`

The capability has a plausible independent boundary: confirm actual Yorùbá/English technical-term changes and, with separate write authority, maintain a canonical validated bilingual CSV glossary.

The closest stable neighbours do not currently own the same result:

- `technical-writing` owns technical prose clarity and reuses established vocabulary; it does not own term confirmation or a bilingual glossary artifact;
- `amose` owns project/domain semantic clarification and canonical project language; it does not inherently own a cross-task Yorùbá/English glossary or its CSV write contract.

That structural plausibility is insufficient for a **new public selector**. Kọ's admission gate requires realistic positive and closest adjacent-negative boundary proof before adding a public owner, including an Experimental one. Experimental placement only avoids a false stable-maturity claim.

**Admission evidence required before #85 merge:** D17 positive term/glossary case plus D18 `technical-writing` and D19 `amose` adjacent-negative cases from `docs/evals/assurance-closeout.md`, on the behavioral hosts required by the current support claim.

If those cases pass, Experimental incubation may merge. Real-use recurrence, incremental value, cost, and boundary-health evidence remain required later for `PROMOTE | KEEP_EXPERIMENTING | NARROW/FOLD | REPLACE | REMOVE`.

### S-05 — Local session evidence script passes the bundled-script boundary

**Disposition:** `KEEP`

The `ayewo-igba-ise` session adapter owns only the corpus-scale mechanical seam:

```text

→ privacy-preserving session/root inventory + structural evidence signals
```

It does not classify eligibility, skill value, mis-triggering, causal responsibility, portfolio disposition, or skill edits. It maintains no daemon, telemetry stream, parallel semantic state, or transcript copy. Synthetic tests cover root/subagent grouping, privacy, parse tolerance, optional time boundaries, and conservative skill signals.

This is a deterministic machine-consumer boundary with recurring leverage; replacing it with ordinary agent instructions would increase repeated parsing/privacy/schema-drift risk.

No structural finding proves that simultaneous owner count is the binding selection problem. A reduced profile could improve common-case selection while hiding a legitimate independent result; structure alone cannot establish that trade-off.
