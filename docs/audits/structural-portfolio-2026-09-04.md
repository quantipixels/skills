## Executive verdict

No structural evidence justifies a broad owner-count reduction or installation profile now. The previously suspected Scope Guard fold is rejected structurally. Root Cause and Pẹ̀pẹ̀yẹ remain credible independent Experimental owners whose promotion/fold decisions require real-use evidence. The new Yorùbá Glossary capability has a credible independent artifact/authority boundary but lacked stable-owner admission evidence; #85 correctly incubates it as Experimental. The next portfolio-changing decisions therefore depend on behavioral/local evidence, not more structural refactoring.

## Findings

### S-01 — Scope Guard retains an independent stable result

**Disposition:** `KEEP`

`scope-guard` returns a standalone portable steering contract: exact outcome, task-local exclusions, expected change envelope, smallest proof, expansion gates, and deliberate ceilings. It explicitly does not implement, review, own architecture, or create lifecycle state.

`alaga` correctly carries equivalent minimum-sufficient-mechanism and scope-expansion invariants *inside delivery*, but its native result is a delivered software/build job. Folding Scope Guard into Alága would remove the directly selectable “constrain this task/agent without implementing it” result and would conflate reusable steering with delivery authority.

**Decision consequence:** the earlier fold hypothesis is rejected unless future selection evidence shows the public identity itself causes more harm than value.

### S-02 — Root Cause is structurally distinct from triage and correction delivery

**Disposition:** `KEEP_EXPERIMENTING`

The owner chain is coherent:

```text
se-triage  → establish report validity/classification and next action
root-cause → establish the minimal causal mechanism/sufficient causal set
alaga      → deliver the software/build correction when diagnosis is settled
```

`se-triage` explicitly hands unresolved causal diagnosis to `root-cause`; `root-cause` explicitly excludes correction attempts; Alága consumes a settled diagnosis without owning causal investigation as a separate result.

No braided lifecycle or duplicated authority is structurally present. Structure therefore does not justify `FOLD` or `REMOVE`, but it also cannot prove recurring public-selection value required for `PROMOTE`.

**Revisit trigger:** representative local-session opportunity/value/boundary evidence.

### S-03 — Pẹ̀pẹ̀yẹ has a credible supervision intent island

**Disposition:** `KEEP_EXPERIMENTING`

`pepeye` owns user-requested task-wide continuity across changing owners/candidates/proof states while explicitly refusing routing, planning, implementation, review, publication, or another lifecycle.

Its closest neighbours remain distinct:

- `alarina` selects/sequences owners when routing itself is needed;
- `atona` owns one initiative plan and progression lifecycle;
- `handoff` serializes current state for transfer to another session/agent;
- `pepeye` keeps an already-requested task coherent across those boundaries without taking their native results.

No structural fold target preserves that exact result without braiding authority/lifecycle. The unresolved question is whether users/agents benefit enough from selecting this public identity in real eligible work.

**Revisit trigger:** local-session evidence for eligible supervision opportunities, selected/missed cases, continuity benefit, and recurring cost.

### S-04 — Yorùbá Glossary belongs in Experimental until boundary evidence exists

**Disposition:** `INCUBATE` (implemented in #85)

The capability has a plausible independent boundary: confirm actual Yorùbá/English technical-term changes and, with separate write authority, maintain a canonical validated bilingual CSV glossary.

The closest stable neighbours do not currently own the same result:

- `technical-writing` owns technical prose clarity and reuses established vocabulary; it does not own term confirmation or a bilingual glossary artifact;
- `amose` owns project/domain semantic clarification and canonical project language; it does not inherently own a cross-task Yorùbá/English glossary or its CSV write contract.

However, #85 initially placed the owner directly in the stable Productivity group without the positive/adjacent-negative boundary proof required by the new Kọ admission gate. Experimental placement preserves the hypothesis and ordinary routing while avoiding a false maturity claim.

**Promotion evidence required:** actual term/glossary positive case plus adjacent negatives for ordinary technical writing and domain-model clarification, followed by real-use evidence proportionate to routing risk.

### S-05 — Local session evidence script passes the bundled-script boundary

**Disposition:** `KEEP`

The `ayewo-igba-ise` session adapter owns only the mechanical seam that does not scale safely as repeated ad-hoc model work:

```text
local Codex/Claude JSONL stores + explicit filters
→ privacy-preserving session/root inventory + structural evidence signals
```

It does not classify eligibility, skill value, mis-triggering, causal responsibility, portfolio disposition, or skill edits. It maintains no daemon, telemetry stream, parallel semantic state, or transcript copy. Synthetic tests cover root/subagent grouping, privacy, parse tolerance, optional time boundaries, and conservative skill signals.

This is a deterministic machine-consumer boundary with recurring corpus-scale leverage; replacing it with ordinary agent instructions would increase repeated parsing/privacy/schema-drift risk.

### S-06 — Profiles/default-surface reduction remains evidence-gated

**Disposition:** `DEFER`

No structural finding proves that simultaneous owner count is the binding selection problem. The portfolio already has a router for genuine ambiguity, direct-selection rules for obvious owners, an Experimental maturity distinction, and an authored A/B discovery experiment.

A reduced profile could improve common-case selection while hiding a legitimate independent result; structure alone cannot establish that trade-off. Profiles remain discovery/install projections only if later evidence shows outcome-first presentation is insufficient.

**Revisit trigger:** discovery Arm A/B evidence, then Arm C only if residual visibility-count cost remains material.

## Healthy repetition retained

Some constraints intentionally appear in more than one owner because invocation boundaries differ. Scope/minimum-mechanism guidance in `scope-guard` and `alaga`, exact candidate/evidence boundaries across delivery/review/provider owners, and authority/trust rules in independently invokable provider skills are not duplication defects when each invocation must remain safe/correct on its own.

- Do not fold Root Cause into triage or delivery from structural similarity.
- Do not fold Pẹ̀pẹ̀yẹ into routing/planning/handoff without real-use evidence that its supervision identity lacks value.
