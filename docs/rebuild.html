Implementation decisions

The user's rebuild request authorizes redesign and PR publication. The choices below are implementation judgments made under that scope, not separate user-confirmed preferences.

  • Fold interfaces, not necessary distinctions. Decision confirmation remains distinct from recommendations; presentation cannot invent meaning; review remains independent and read-only.
  • Retain conditional engineering depth. Consumers, domain conversion, framework invocation, tenant boundaries, concurrency, recovery, numerical units, properties and build invalidation remain reachable through cohesive references.
  • Keep the optional host profile. No user configuration is changed and no model, concurrency or spending enforcement is claimed from prose.
  • Remove general machinery deliberately. Retire playbook scaffolding, the session parser, separate HTML controls, experiment bookkeeping and campaign manifests. Preserve provenance rather than copying every historical instruction into the new hot path.
  • Make the break explicit. Removed public identities have migration guidance, not thin aliases. The major changeset advertises the compatibility change.

Migration notes explain every public fold, retired interface, native-invocation limitation and intentionally lost campaign capability.

Premortem and recovery

Primary risk: compressed guidance loses a useful branch or moves burden into callers. Conditional references and explicit migration dispositions address known obligations; actual task trials are still needed to assess behavioral effects.

Compatibility risk: copied installations retain removed names or hosts interpret manual-only metadata differently. Verify the installed identity and explicit command path. Do not silently delete local edits or switch managers.

Evidence risk: deleting campaign machinery loses reproducibility or makes bad outputs easier to pass. Retained oracles and controls remain immutable; historical sources have explicit locators. Private raw runs may still be unavailable, and direct oracle execution is not a hardened sandbox.

Recovery: revert the source change or restore the pinned baseline through its existing manager, then reload and verify the active installation. This cannot reverse effects already performed by an agent or recover external traces. Keep the original integration branch untouched until the human merge decision.
