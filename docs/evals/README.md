# Behavioral evaluation index

QP keeps evaluator-owned behavioral evidence separate from runtime skill guidance. Use fresh contexts, record the exact candidate identity and host/model, and never convert model judgment into grep/keyword CI.

## Packs

- [`stacked-pr-stewardship.md`](stacked-pr-stewardship.md) — stacked PR/MR stewardship, publication boundaries, and activation. Run its critical wave first, then the preservation wave when critical behavior passes.
- [`portfolio-discovery.md`](portfolio-discovery.md) — current-surface versus outcome-first discovery, with a reduced/profiled arm blocked unless A/B prove simultaneous visibility remains a material problem.
- [`assurance-closeout.md`](assurance-closeout.md) — prior-contract comparison, first-touch/invocation-mode behavior, Kọ public-owner admission reasoning, Kọ stable-skill improvement reasoning, and the Codex/Claude behavioral-host boundary.

Owner-specific public-admission cases belong with the owner candidate that needs them rather than in the reusable assurance pack.

## Evidence boundary

Structural/package/compatibility CI proves deterministic obligations only. A behavioral row becomes `PASS` only from the fresh-context run specified by its pack. Use `PASS | FAIL | BLOCKED | NOT_RUN | STALE` and record enough notes to explain the decision, not the evaluator's hidden expectations.

Do not manufacture a generic eval runner merely to centralize these packs. Use a host-native fresh session or an already-available evaluation capability; add persistent machinery only if repeated execution friction itself becomes a demonstrated problem.
