# Browser visual reasoning

Use when HTML needs shaped visual reasoning beyond prose or a table. Make the supplied relationship inspectable: label decisive branches, align comparable specimens, preserve common scales/units and place the consequence beside the view.

Use semantic HTML/CSS for aligned specimens and simple stages, SVG or a structured diagram grammar when paths/spatial relations carry meaning, quantitative charts for magnitude/trend/distribution, and graph tools for dense connected structures. Mature capabilities are allowed and nonexclusive; choose representation before renderer, revalidate current APIs and use the lightest delivery that preserves the reader job.

Keep entity identity, labels, scale and semantic color roles stable across views, with non-color cues. Support focus/selection as well as hover. Linked highlighting preserves context; filtering removes it and therefore needs an explicit result and reset. Large or interactive structures need accessible equivalent meaning.

For assurance or traceability, show the exact claim → evidence → disposition or acceptance → contract → implementation → proof links, including stale/broken conditions. Use only owner-established orphan gaps; page topology cannot prove semantics. Candidate comparisons share visual grammar and hard gates remain distinct from scores.

Preserve source identity, cutoff, freshness and observed/inferred/proposed/illustrative status. Polish and interaction add no authority. Structural proof checks the modeled relationship, critical coverage, source mapping and fallback; browser proof covers only material layout, renderer, interaction or accessibility claims.
