# Browser visual reasoning

Use for shaped relationships beyond prose/table composition. Reuse the reader task and presentation from fihanmi or an accepted design; oro owns prose, and HTML Artifact owns browser representation.

Start with the [visual toolbox](visual-toolbox.md). Label decisive branches, align specimens, preserve scales/units and put explanations beside the view. Adjacent cards do not express a branching flow. Rounded diagram nodes are fine when their edges carry meaning.

Use semantic HTML/grid/flex for alignment and lanes, SVG for exact spatial marks, Mermaid for structure and focused charts for quantities. A div cannot replace a button, table, heading or labelled figure. Mature renderers can remove fragile bespoke work without dictating a visual style.

Preserve identity, labels, units and meaningful colour across views. Linked highlighting preserves context; filtering removes it, so show count/reset. Support focus/tap rather than hover-only essentials. Keep control/reading positions stable. Colour can be expressive; when it encodes evidence, provide stable meaning plus non-colour cues. Monochrome is valid.

## Coverage and traceability

The smallest sufficient view retains human-critical conditions and uncertainty. Select per relationship, not per Markdown heading. Several sections may form one trace; one section may need a diagram and specimen.

Expose claim → evidence → disposition or acceptance → contract → implementation → proof with freshness. Counts/health percentages cannot replace actual links. When required, reason backwards: an obligation may lack proof, an implementation may lack accepted basis, or evidence may be stale. Those judgments belong to the source owner, not graph topology.

## Compare and explain honestly

Align alternatives on common criteria, scale and labels. Comparative scoring retains hard gates and assumptions; confidence/readiness are not one numerical score. Use a table for lookup, a plot for quantitative patterns and a graph for connected structure. Dense interactive views require an accessible equivalent.

Visual weight must reflect supplied relationships; arbitrary rectangle sizes are not measured complexity. Cross-sections can show data, trust, lifecycle, recovery or proof at a boundary without pretending these are quantities.

After representation selection, use [representation capabilities](representation-capabilities.md) and [dependency policy](dependency-policy.md). Keep renderer choices open. A static document does not gain a live service by implication. Use [interactive projections](interactive-projections.md) only for reader value and default transient state. Structural proof checks source/model/fallback; browser proof checks introduced layout and interactions. Polish never strengthens source authority.
