# Instruction economics

Read when agent-facing wording or structure may change selection, attention, context pressure, completion or behaviour. Optimize behavioural leverage per unit of context, rather than word count alone.

Diagnose missed constraints, irrelevant retrieval or lost evidence before prescribing a reset or larger window. No project-wide token percentage proves reliable attention. Summaries and handoffs must retain the active outcome, authority, candidate, unresolved obligations and exact evidence locators. Reopen primary material when a decision needs omitted detail; compaction does not reset settled work.

## Place attention deliberately

Two loads matter: **context load**, which the agent receives whether useful now or not, and **human cognitive load**, which a person must remember to invoke or maintain. Model-reachable guidance trades more context for less human memory; human-only guidance does the reverse.

Use this hierarchy:

1. **Hot path** — what every invocation needs.
2. **Local reference** — cohesive expertise commonly consulted together.
3. **Conditional reference** — branch-specific depth behind a reliable pointer.

A **branch** requires different behaviour. A **pointer** names its capability and load condition. Front-load the term that distinguishes the branch: `Database concurrency — load when coordinating mutable shared state` is reachable; `More guidance — read when useful` is not. Name an exact known skill rather than a vague owner.

Keep universal authority, evidence and completion rules on the hot path. Put mechanical rules in an existing enforcement mechanism that can reject violations; callers point to that owner. Review can load detailed judgment standards, but construction still needs its governing constraints. Co-locate definitions, rules, caveats and examples normally used together; fragmentation can increase load even without duplication.

## Compress decisions, not meaning

Prefer established terms that carry a useful distinction. A **bound** names observable completion; **no-op** names guidance that adds no useful behaviour over the capable baseline; **cache** names a copied fact cheaper and fresher to inspect; **sediment** names stale guidance retained through habit.

Use an engineering principle's name when it makes the required decision more precise or compact. A blanket acronym list supplies no contract. Expand unfamiliar abbreviations and coin terms only when repeated use repays their decoding cost. Keep precise domain terminology.

A bound needs both clarity and demand. `Account for every changed public contract` can prevent premature completion; `Review carefully` cannot. Tighten a weak bound before adding staging or isolation.

State the desired behaviour directly: `Name the exact skill and useful variant.` Keep explicit prohibitions for hard boundaries or demonstrated failure modes.

## Remove load by effect

Delete no-ops, cheap caches, duplicate meaning, sediment, superseded mechanisms and exposition that changes neither judgment nor execution. Delete the whole obligation when it no longer earns load. Keep one authoritative meaning and retain repetition only for a distinct trigger, authority boundary, recovery condition or independent check.

Next, move branch-specific expertise behind a clear pointer, compress repeated explanations and shorten constructions. Keep examples that clarify output, replace prose, reduce reader effort or prevent a plausible wrong action.

Compare realistic work with and without guidance before making frontier-capability claims. A capable baseline can justify deleting generic scaffolding; it does not establish that specialist expertise, routing topology or a hard boundary is unnecessary. Use the [placement classes](skill-mechanics.md#classify-before-adding-guidance) for an addition, and [editing agent text](editing-agent-text.md) for material pruning and its semantic checks.

Leave provider mechanics (spawn syntax, parallel scheduling, joins, status transport, retries, PR watching, scheduling) to the host and SIGIDI. Do not add "discover relevant skills", "parallelize independent work", "wait for all workers" or similar generic rules unless evidence shows the target model fails without them. Do not create an agent definition merely to name a worker; shape workers through the assignment.

Stop when the next cut would require consequential guessing about behaviour, authority, evidence, coverage or recovery. Word count describes compression, not improvement.
