# Àdánwò

Output: a confirmed direction and clearer needs, from prototypes that are disposable (a working record of kind prototype when persistence helps iteration). Prototypes are not delivery code, and a prototype request does not authorize production changes, publication or adoption.

Needs: the idea to try and the decision it should inform. If those are missing, return and say what is missing.

## Method

**Workflow** (`asoju`): an unsettled abstraction, interface or approach is raced: two candidates, a rubric set first and hidden from them, and an independent cross-judge.

- Reuse the known audience, outcome, constraints and preferences. Identify what experiencing a prototype could clarify. Start with a provisional question when the need is still emerging; ask only for what materially changes the first useful round.
- Choose the smallest medium that makes the experience truthful: a sketch for visual direction, an interactive flow for behaviour, a runnable API or CLI for ergonomics. Label simulations and never fake the dimension being explored. Reuse existing components.
- Show a web prototype in the host's browser and a mobile one on a device or simulator; close what you open. A single standalone HTML page can be generated (by `ojuiwe`).
- Keep prototypes in temporary storage by default. Stay within existing authority for edits and external effects.
- Defaults: a UI prototype is three versions that differ in idea (layout, flow or interaction), unless the user asks for one; a costly-to-change abstraction or interface gets two tiny versions raced with `asoju`.
- Explore distinct directions, then narrow with the user; read [directions and rounds](references/directions-and-rounds.md) for variants, the race for costly-to-change abstractions, and the narrowing loop.

## Done

The user confirmed the direction and the needs it serves, ended the exploration, or a concrete gap blocks further work. If no direction was confirmed, say so plainly. Direct experience supports only the dimensions actually represented; it does not show production readiness or an objectively best design.

## Return

The selected direction and artifact locator, the reasons, confirmed needs and constraints, unresolved choices, and simulated behaviour. Carry the brief, useful assets and interaction decisions; retain artifacts needed for review or resumption, and discard only owned temporary work after its evidence is captured.
