# Àdánwò

Make ideas tangible so the user can discover, compare and shape the outcome they want. The result is a confirmed direction and clearer needs; the prototypes are disposable.

## Frame enough to start

Reuse the known audience, intended outcome, constraints and user preferences. Identify what experiencing a prototype could clarify. Start with a provisional question when the need is still emerging; feedback may reshape it. Ask only for missing information that materially changes the first useful round.

Choose the smallest medium that makes the relevant experience truthful: a sketch for visual direction, an interactive flow for behavior, or a runnable API/CLI for ergonomics. Label simulations and never fake the dimension being explored. Reuse existing components and preview capabilities when useful.

Keep prototypes in temporary storage by default, or `.qp/adanwo/` when persistence helps iteration. Stay within existing authority for edits and external effects; a prototype request does not authorize production changes, publication or adoption.

## Explore distinct directions

Build the requested number of variants, or choose a useful range proportionate to the uncertainty and effort. Ten variants can be appropriate; ten cosmetic variations rarely clarify ten different possibilities. Give variants stable labels and explain the meaningful idea each explores. Keep them comparable on the current question and at enough fidelity for useful reactions.

A single prototype is sufficient when it can resolve the uncertainty. Use relevant design or implementation skills for craft while keeping this work disposable.

## Narrow and combine with the user

Present an inspectable or runnable path and a focused feedback prompt. Let the user identify what works, what fails, what is missing and why. They may keep parts of several variants, reject all of them or reveal a different need. Record actual reactions separately from your interpretation; silence or an agent's ranking is not user preference.

Use each round to eliminate weak directions, preserve the reasons behind preferences and combine compatible strengths. Make the next round smaller or more focused when the evidence supports narrowing. Verify combinations as a whole: individually liked parts may conflict when joined. Introduce a new direction when feedback exposes a gap rather than forcing a winner from the initial set.

For example: ten distinct designs → three preferred directions → two combined prototypes → one refined direction. The counts and rounds follow the user's feedback; they are not a quota or fixed tournament.

Update the emerging brief as understanding changes. Keep settled preferences unless new feedback challenges them, and make consequential changes in the question visible. Continue until the user confirms the direction and the needs it serves, ends the exploration, or a concrete gap prevents further useful work. If feedback is pending, leave the choice open.

## Carry forward the learning

Return the selected direction and artifact locator, the reasons for it, confirmed needs and constraints, and any unresolved choices or simulated behavior. If no direction was confirmed, state that plainly. Direct experience supports only the dimensions actually represented; it does not establish production readiness or an objectively optimal design.

Carry forward the brief, useful assets and interaction decisions. Disposable implementation is not accepted delivery code by default. Retain artifacts needed for review or resumption; discard only owned temporary work after its useful evidence is captured. Use `alaga` for an authorized implementation, `arojinle` when broader consequential decisions need an interview, and `iwadi` when an unresolved factual question needs research.
