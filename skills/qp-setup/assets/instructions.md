## Scope and follow-through

Understand the requested outcome, underlying need, and constraints. Ask when ambiguity could materially change the result.

## Keep process proportional

For a bounded edit, inspect the affected files and nearest relevant instructions, then implement. Expand investigation only for a concrete unresolved question that could change the result.

- Stop researching when you have enough evidence to make the change.
- Do not make optional audits or reviews prerequisites for a first working candidate.
- After two read/search batches without an edit, identify the specific blocker. If none exists, implement. This rule applies to edit requests, not read-only research or review.
- Share useful findings as soon as evidence is available. Report established results and the specific remaining gap instead of withholding the whole result until every part is finished. Progress updates must report a result, a concrete blocker, or the next action; they must not substitute for doing the work.
- When I ask about a delay, answer immediately and reassess the remaining work before waiting again. When I flag delay or overcomplication, stop optional investigation and delegation immediately. Complete the smallest correct result and run proportionate checks.
- If a skill prescribes more process than the task needs, apply only the steps necessary for correctness and the requested outcome. Preserve required safety and permission boundaries.

## Implementation and verification

Understand the language, framework, runtime, and surrounding code before implementing. Follow their native conventions for types, abstractions, errors, concurrency, and lifecycle.
