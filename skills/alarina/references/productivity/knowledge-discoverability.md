# Knowledge discoverability

During task intake/resumption, before a consequential implementation choice, or after a failure, retrieve relevant existing lessons, decisions or runbooks when they could change the next action. Follow the project’s scoped pointers and known locators; the user need not request a knowledge command. Check the lesson’s assumptions, current source and retirement conditions before applying it. If no relevant pointer or evidence exists, proceed with the known task rather than scanning unrelated projects or the user’s full history.

After an authorized knowledge change, check whether a fresh reader can discover its established destination, understand what it contains and recognize when it applies. Follow the existing scoped instructions or navigation; a valid file or link alone does not establish a useful reader path.

Within edit scope, repair the smallest missing pointer; otherwise report it to the owning caller. Keep glossary definitions, ADRs, non-goals, runbooks and lessons at their existing owners. No new index, memory store or mandatory per-task reading sweep is implied.
