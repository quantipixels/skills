References are grouped by use case, not the command that first used them. Any caller can reuse relevant guidance while retaining its requested result, authority and stopping point. ## Find depth and compose around a gap

Compare the requested outcome and accepting evidence with the current method's coverage. Name the uncovered result, decision or proof before searching. Use the command menu for result owners and the relevant topic above for supporting expertise. The table is a starting map: inspect filenames and headings, then search relevant topic contents for the actual concern, including adjacent topics when it crosses boundaries. Read promising references in full before applying them; neither a keyword match nor a familiar filename proves fit. Stop discovery when the remaining obligations have an adequate path, rather than surveying every reference.

For example, a recovery task may need diagnosis plus stateful proof and shared-state architecture guidance; a mixed explanation may need domain context, visual representation and human-facing writing without a matching playbook. Use a command when its owned result is needed, or apply a reference directly within the caller's task. Preserve each method's authority and return its evidence to the task owner. If nothing covers a gap, use available project/native/external expertise within scope or report the missing capability. Do not force a poor match or create a permanent workflow merely to finish this task.

Add depth to an existing topic when it fits. Introduce a topic only when it gives callers a useful selection boundary; avoid folders named for owners or an ambiguous miscellaneous bucket. Update this guide when discovery changes, without turning it into an exhaustive file inventory.
