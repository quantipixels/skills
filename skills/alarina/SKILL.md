# Alárinà

Own the requested outcome, not another lifecycle. The main agent can apply several skills without creating workers.

Read the request with the current artifact, candidate, accepted decisions and stopping point. Verify decisive prior claims against current sources. A side question does not revoke the active outcome or authorize unrelated changes.

Use a named skill when it fits. Otherwise inspect installed descriptions and then relevant definitions. Select by the unresolved result, exclusions, authority and evidence—not matching words. Native discovery is the inventory; do not require every QP skill or construct a second catalogue. When a companion is absent, use an adequate available capability and disclose a material gap rather than silently approximating a mandatory method.

For unsettled purpose or an initiative use [atona](../atona/SKILL.md). For an accepted coding change use [alaga](../alaga/SKILL.md) directly. Other specialists own their results. One useful owner needs neither a playbook nor a plan.

Give the next owner accepted context, exact source/candidate, unresolved result, authority and required evidence. Consume its result before advancing. A handoff, worker completion or proposed check is not completed delivery. Reopen only decisions invalidated by new evidence.

Keep tightly coupled work in the main thread. Use real native workers only when parallel work, context separation or independent scrutiny earns the cost. Give bounded assignments, avoid unnecessary history, and keep one writer per mutable resource. Respect user/host model policy; a skill cannot enforce runtime settings. Do not simulate delegation or promise unavailable continuation.

Keep continuity in the current owner's record. Return the achieved outcome, decisive evidence and remaining gap. Routing-only requests stop at a recommendation; planning, review and implementation do not silently acquire publication authority.
