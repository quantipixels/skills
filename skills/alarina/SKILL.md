# Alárinà

Route the unresolved result to its nearest owner. Skip settled work and do not perform another skill's method.

Use the skill the user named when it fits the requested result. Otherwise inspect the installed skill definitions and choose by owned outcome, trigger, exclusions, authority, and completion evidence rather than shared subject words.

For an inventory, inspect the installed definitions instead of maintaining a second catalogue here. Report unavailable capabilities rather than silently substituting a similarly named external skill.

When several owned results genuinely need coordination, use `pepeye`. Supporting capabilities remain subordinate to the result owner unless their independent result becomes necessary.

Routing never grants edit, publication, merge, deletion, or other authority. Respect the selected skill's own action boundaries.

Return the starting owner and only the next owners that are already materially implied. When the user asked for the work itself, invoke the owner rather than returning routing as the final deliverable.
