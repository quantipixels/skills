# Release and rollout

Use to plan or execute the release of an accepted candidate, including package publication and service deployment. PR readiness alone stays with [wo-pr](../commands/wo-pr.md). Preserve the requested environment, effects and stopping point.

1. Recover the exact candidate, required consumer compatibility, existing release process and current acceptance evidence. [atona](../commands/atona.md) owns necessary sequencing and rollout readiness in the current plan/runbook; [architect-design](../commands/architect-design.md) resolves consequential coexistence or recovery design.
2. [alaga-deliver](../commands/alaga-deliver.md) supplies missing candidate or consumer proof. Use Data change only for an unresolved populated-data obligation within that same plan. Reuse current tests and checks; release coordination does not require a second verification suite.
   Reconcile required documentation against the exact release candidate and intended audience, reusing applicable delivery evidence. Use [akowe-audit](../commands/akowe-audit.md) for unresolved documentation readiness or [akowe-sync](../commands/akowe-sync.md) for authorized corrections. Distinguish candidate docs, supported-version guides and the published site; documentation publication remains a separate authorized release action.
3. Stop with the plan or readiness judgment when that is the request. For authorized execution, use the project's release capability and native provider tools. [seda-pr](../commands/seda-pr.md) owns any requested Git review publication; registry publication and deployment retain their actual project owner.
4. Verify the released version or deployed candidate through its real consumer boundary using the project's verification capability. Return actual observations to the same plan. On partial failure, reconcile what took effect before resuming or recovering; do not overwrite a published version or replay irreversible actions by default.

Finish with the actual release/deployment state, observed acceptance and remaining recovery or monitoring obligations. A merged PR, successful upload or green readiness check does not establish live acceptance; use only observation windows the host can actually sustain.
