# Investigation

Use for an evidenced answer, diagnosis or recommendation. Runtime forensics concerns a live symptom; trace forensics starts from a supplied capture. Neither implies a fix.

1. Identify the question and the evidence that could change its answer. Use a subject specialist for a bounded explanation, `iwadi` for substantial research, or `alaga` in diagnosis mode for an observed failure. Challenge a consequential proposal through Alárinà's premise check.
2. For runtime evidence, give `alaga` the actual symptom or capture. Use the project's runtime capability when obtaining or interpreting a profile, heap, thread dump or trace needs tooling expertise. Relevant project verification capabilities may supply an authorized reproduction; their output is evidence for the diagnosis.
3. Let a missing fact determine the next bounded probe. A hotspot, correlation or previous repair narrows the question; it does not settle the causal mechanism. Keep tool failure and unavailable runtime evidence visible.
4. Return the supported answer, decisive evidence, alternatives that remain live and the smallest unresolved discriminator. Preserve a substantial reusable research result through `iwadi`.

Stop at the requested answer. Propose a next step when useful; enter correction or comparative optimization only when the request also authorizes that outcome. A blocked live probe does not justify replacing observed evidence with an invented result.
