# Bug fix

Use for a defect that needs diagnosis and repair, or evidence about a supplied repair. A known cause and accepted correction can enter `alaga` delivery directly.

1. Use `alaga` issue intake when report validity is open, then diagnosis when the cause is open. Carry the reproduction, relevant existing data and confirmed mechanism between modes. Suite-order dependence, crossed component boundaries and confirmed variants select Alága's bounded diagnosis methods when relevant.
2. If a candidate repair already exists, ask `alaga` for the existing-repair comparison before creating another fix. A verification-only request ends at that comparison; a missing baseline remains a proof gap.
3. Resolve only choices that still control the correction. Use `architect` for consequential structure, `atona` when several dependent outcomes need a plan, and `arojinle` for a requested interview or dependent user decisions. Do not re-plan an accepted fix.
4. `alaga` delivers the bounded correction and proof against the original failure and required behavior. Use an applicable project verification capability for the real affected boundary. Let `atunwo` supply independent judgment when requested or materially useful; return warranted findings to `alaga` and refresh affected proof.
5. Continue to `wo-pr` only for authorized publication or requested readiness work. Retain any unverified runtime obligation in the completion report.

Finish at the requested repair and its accepting evidence, or at the explicit intake, diagnosis or comparison bound. A passing test count alone does not close the defect.
