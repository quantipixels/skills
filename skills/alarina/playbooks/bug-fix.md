# Bug fix

Use for a defect that needs diagnosis and repair, or evidence about a supplied repair. A known cause and accepted correction can enter [alaga-deliver](../commands/alaga-deliver.md) directly.

1. Use [alaga-intake](../commands/alaga-intake.md) when report validity is open, then [alaga-diagnose](../commands/alaga-diagnose.md) when the cause is open. Carry the reproduction, relevant existing data and confirmed mechanism between modes. Suite-order dependence, crossed component boundaries and confirmed variants select Alága's bounded diagnosis methods when relevant.
2. If a candidate repair already exists, use [alaga-compare](../commands/alaga-compare.md) for the existing-repair comparison before creating another fix. A verification-only request ends at that comparison; a missing baseline remains a proof gap.
3. Resolve only choices that still control the correction. Use [architect-design](../commands/architect-design.md) for consequential structure, [atona](../commands/atona.md) when several dependent outcomes need a plan, and [arojinle](../commands/arojinle.md) for a requested interview or dependent user decisions. Do not re-plan an accepted fix.
4. [alaga-deliver](../commands/alaga-deliver.md) delivers the bounded correction and proof against the original failure and required behavior. Use an applicable project verification capability for the real affected boundary. Reuse its TDD review stage or other requested/warranted [atunwo](../commands/atunwo.md) judgment; keep specification and standards/refactoring conclusions distinct. Return accepted findings to Alága and refresh affected proof.
5. Continue to [seda-pr](../commands/seda-pr.md) for authorized publication or [wo-pr](../commands/wo-pr.md) for requested readiness work. Retain any unverified runtime obligation in the completion report.

Finish at the requested repair and its accepting evidence, or at the explicit intake, diagnosis or comparison bound. A passing test count alone does not close the defect.
