# Skill evaluation and improvement

Use when retention of a skill, instruction or routing change depends on actual comparative outcomes. Ordinary wording fixes go directly to `oro`; a request to evaluate ends at the supported result unless adoption is also authorized.

1. `oro` identifies the proposed behavioral change, current owner and expected effect. Keep the source candidate exact. If an observed failure needs explanation before a remedy can be chosen, use the existing diagnosis or postmortem owner for that gap.
2. `adanwo` owns the bounded comparison, using its agent-evaluation and applicable judged-outcome guidance. Use `irinse` only for necessary host readiness or discovery work. Native hosts own model execution, isolation and worker lifecycle.
3. Consume actual artifacts and execution evidence. A structural check or a routing answer alone cannot establish end-to-end improvement. Keep missing access, invalid trials, failures and inconclusive differences visible; do not replace an unavailable run with a fabricated transcript.
4. Return the evidence-backed retain, reject or inconclusive result. With adoption authority, `oro` finalizes the chosen instructions; refresh affected comparisons if finalization changes measured behavior. `irinse` handles installation only when requested, and `wo-pr` handles authorized publication.

Finish with the exact compared candidates, observed benefits and costs, limits, and actual adoption state. A winning supplied-candidate trial does not prove that the host will automatically discover the installed skill.
