# Àyẹ̀wò — cross-session evidence

Assess patterns across a bounded set of coding sessions or generated artifacts: recurrence, skill opportunities and use, observed costs, or justified reusable-resource candidates. Read the [shared retrospective method](../references/engineering/retrospectives/postmortem-method.md) and [corpus analysis](../references/engineering/retrospectives/corpus-analysis.md).

Pin the population, independent roots, selection basis and coverage before making cross-session claims. Use [session analysis](../references/engineering/retrospectives/agent-session.md) for each sampled coding session when reconstructing environment or instruction failures. For generated outputs and their producing history, also read [artifact pattern mining](../references/engineering/retrospectives/artifact-pattern-mining.md). Use the existing [session indexer](../references/engineering/retrospectives/local-session-evidence.md) only when its structural inventory is needed; it supplies no semantic verdict.

Return supported patterns, counterexamples, denominators when known, evidence gaps and earned recommendations with owners. Artifact candidates include their fixed contract, free canvas and promotion judgment. A recurring pattern is not proof that an instruction change improves outcomes; use the [skill-evaluation playbook](../playbooks/skill-evaluation.md) when a controlled comparison is needed.

Keep one-session environment improvement with [ayewo-retro](ayewo-retro.md), and an event narrative with [ayewo-igba-ise](ayewo-igba-ise.md). The shared method permits retaining qualified custom workflows within write scope; other remediation remains a recommendation unless authorized. Do not manufacture invocations, broaden private-history collection, add telemetry or publish evidence merely to strengthen a claim.
