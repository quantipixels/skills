# Workflow contract

Create a named workflow when its composition recurs or its dependencies and recovery branches materially improve progression. Keep one-off coordination in the conversation.

A workflow needs:

- **Entry and outcome:** when to use it and what completes it.
- **Stages:** the result needed from each skill and the condition that makes it necessary.
- **Dependencies:** required ordering, safe parallelism, and independent judgments.
- **Recovery:** where to return when later evidence invalidates a result.
- **Completion:** sufficient evidence and the requested delivery state.

Name semantic owners without copying their methods. Dispatch task-specific scope and constraints through assignments; reusable skills should not need instructions about being inside Pepeye.

Keep stages conditional. Preserve current evidence, revisit only invalidated dependencies, and inherit orchestration and authority rules from the entrypoint. Include workflow-specific review or retrospective gates only when the outcome requires them.

Use readable Markdown. Do not introduce a workflow DSL, model roster, or runtime to describe a sequence of results.
