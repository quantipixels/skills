# Alárinà

Route only when routing itself is needed. If one current skill clearly owns the requested outcome, select that owner directly and do not expose the supporting capabilities it may use internally.

Current repository skill metadata is the inventory. Do not maintain another prose catalogue of the portfolio.

## Route rules

1. Pin the requested outcome, current work state, supplied exact-current results/artifacts, active owner when known, and explicit skill/mode choice.
2. Respect an explicit valid owner selection and host invocation metadata.
3. When one owner can accept the current state and produce the requested outcome, start there and stop routing.
4. Add another owner only when it produces an independently useful result or owns a distinct authority/completion boundary that the current owner cannot absorb. Conditional internal support is not a route stage.
5. Enter at the current state; do not replay settled exploration, planning, design, execution, review, publication, or retrospective work.
6. Pass only the exact result/context needed across a real ownership boundary. Do not become a transcript store, receipt schema, lifecycle, coordinator, or map of internal composition.
7. Stop at the requested outcome. Do not append review, publication, documentation, persistence, handoff, or retrospective merely because it often follows.

When metadata leaves two plausible independent owners genuinely ambiguous, distinguish them from their native outcomes, authority, and completion boundaries rather than from a maintained pairwise routing table. Add a durable routing exception only when repeated evidence proves metadata remains insufficient.

When no repository skill materially improves the result, return `NO_ROUTE` and let the calling agent use ordinary host/domain capability. Do not force a request through the nearest QP owner merely because the portfolio lacks a specialist. Routing grants no mutation, provider, credential, publication, review-verdict, or continuing-stewardship authority.

## Report

Return only public ownership transitions:

```text
Start: <current owner + why>
Then: <next independently useful owner + why, only when ownership must change>
Activation: <direct-user activation required by host metadata, or none>
Stop: <requested outcome>
Why not: <closest materially different route, only when it resolves real ambiguity>
```

For an inventory request, enumerate current repository skill metadata rather than reproducing this report shape. Ask one focused question only when it selects a materially different owner and current evidence cannot answer it.
