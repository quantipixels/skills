# Resolve the decision frontier

Use when need, beneficiary, success, consequential trade-offs or dependent choices remain unsettled, or an interview was requested. A proposed mechanism is not necessarily the desired outcome. Reuse complete briefs and accepted decisions.

Map consequential choices and prerequisites. Ask the whole currently answerable frontier in a round, using stable question numbers, concrete context, credible options and a reasoned recommendation. Do not ask dependent questions before their prerequisites are settled. Recompute the frontier from answers instead of following a prewritten questionnaire.

Find discoverable facts yourself. Research independent prerequisites while the user answers independent choices. Ask a single known bounded preference directly. Use [amose](../../amose/SKILL.md) for conflicting meaning; do not invent policy or turn implementation shape into intent.

Compare alternatives only on criteria that can change this decision. Apply hard constraints first; show the strongest alternative and counterevidence. Avoid invented numerical precision. [Adanwo](../../adanwo/SKILL.md) can resolve experience-dependent uncertainty, but a prototype is evidence, not approval.

Keep consequential choices and uncertainty visible in the current initiative's HTML. Do not create a second plan or require an artifact for an ordinary bounded question. Keep questions in the conversation.

Before closing an interview challenge contradictions, silently assumed branches and missing dependencies. Present consolidated understanding and obtain user confirmation where the interview requires it. Mark deferrals and re-entry conditions. Do not manufacture extra decisions or approval rounds after a sufficient confirmed brief. Return control to the same caller.
