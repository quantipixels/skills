# Portfolio audit

Use only for a bounded read-only portfolio audit. Reapply Kọ Skill's normal authoring model to existing packages; do not edit, install, activate, synchronize, or publish skills.

## Pin the inventory

Record repository/root scope, package/router surfaces, exclusions, observation time, and authority. Track `source | installed | active | published` independently when relevant; changes to an observed surface stale dependent parity evidence.

## Audit ownership and composition

Run applicable deterministic package/link/manifest/name checks. Structural success proves structure only, not behavioral quality.

Map recurring public outcomes to primary owners and necessary supporting results. Flag:

- competing owners or public splits driven mainly by taxonomy;
- support-shaped public skills whose separate identity adds routing/cognitive surface without simplifying direct selection/use;
- caller copies of callee procedure/result schema or callee copies of caller lifecycle;
- supporting owners/references that originate or redefine consumer semantics, acceptance, authority, freshness, priorities, or verdicts;
- explanatory neighborhood topology and duplicated owner catalogues that do not carry a real selection, result-consumption, handoff, or authority boundary; and
- semantic units projected one-to-one onto commits, branches, PRs/MRs, tests, sessions, or other operational containers without an independent integration/evidence reason.

Preserve independently required safety/trust/authority rules and useful named steering contracts. A reference may deepen method but must not widen its parent owner or establish a second semantic owner.

Verify cross-skill identifiers against current frontmatter metadata. Classify control shape only when it helps expose unnecessary workflow ceremony; importance alone does not justify lifecycle machinery.

## Audit instructions before size

For each consequential instruction or recurring cross-owner path, establish only what changes the disposition:

```text
default capable-agent tendency
→ material owner-specific failure
→ deliberate behavioral override
→ value gained
→ recurring cost
→ exact trigger
→ adjacent-owner interaction
```

Use these dispositions when useful:

- `ESSENTIAL_OVERRIDE` — default model behavior is materially wrong for this outcome;
- `HIGH_VALUE_CALIBRATION` — the instruction reliably improves judgment/result despite a capable default;
- `SAFETY_AUTHORITY_INVARIANT` — independent invocation must preserve it;
- `CONTEXT_ISOLATION` — isolation deliberately protects reasoning/continuity/independent observation;
- `OPERATIONAL_ANCHOR` — a small concrete pointer prevents repeated rediscovery of an already-selected capability;
- `RECOVERABLE_DEFAULT` — a capable agent already performs it adequately;
- `WRONG_OWNER` — useful behavior, incorrect placement;
- `MIS_TRIGGERED` — valuable behavior activates too broadly/narrowly; or
- `HARMFUL` — it predictably pushes the result in the wrong direction.

Do not classify deliberate friction as bloat merely because it is expensive. Challenge whether its trigger and cost still protect the owned result.

### Residual decision surface

For compression, consolidation, owner broadening, framework/reference removal, or genericization, compare the **material decision surface** before and after. Ask which choices are newly exposed and whether each is:

- determined by current evidence/contract;
- explicitly owned by a user/domain/specialist authority;
- legitimate local discretion that cannot materially change the owned outcome; or
- still surfaced as an unresolved gap.

Flag any consequential choice that became unlabeled model inference. Do not count decisions or invent a score; judge the material consequences and evidence boundary.

### Named models, standards, and concepts

When a change removes a named framework/model/standard, use [reference quality](reference-quality.md). Preserve the name when it materially provides conceptual compression, stable vocabulary, authoritative scope, a discriminating lens, or a useful retrieval anchor. Do not preserve it merely for prestige, methodology ceremony, generic templates, or latent rules outside the skill's intended subset.

Simulate representative end-to-end paths rather than auditing skills only in isolation. Flag cascades only when a step does not independently protect the requested result or repeated correction cannot converge without unauthorized scope expansion.

## Audit capability/resource placement

Apply [capability and resource placement](resource-placement.md) to material commands, references, scripts, templates, data, assets, libraries, public owners, and operational anchors. Do not duplicate its placement test here.

Apply [reference quality](reference-quality.md) to substantial expert depth, [script boundary](script-boundary.md) to surviving executable capability, and [knowledge catalogues](knowledge-catalogues.md) only when a maintained researched corpus is itself part of the public result.

Challenge templates/default state/support assets that exist for convenience rather than a stable recurring contract. Existing project/native scaffolds outrank bundled starters; optional behavior remains conditional unless representation/control is itself part of the owner contract.

## Experimental portfolio judgment

When the audit must decide an Experimental skill's portfolio disposition, read [experimental skill disposition](experimental-disposition.md). Ordinary structural audit evidence cannot establish historical usage or incremental value.

## Presentation, drift, and proof

Audit whether Markdown exposes behavior-bearing structure rather than hiding a checklist in dense prose. Use prose for connected rationale, bullets for parallel obligations, numbered lists only for real sequence, tables for finite mappings/states, and fenced blocks for exact contracts. Do not reward formatting volume by itself.

Search for stale links, obsolete commands/names, duplicate active guidance, unreachable references, and historical research presented as current contract.

For compression/consolidation, require realistic before/after proof only where material uncertainty remains. For model-steering changes, compare the same bounded task when the intended behavioral delta is uncertain. Size reduction is not acceptance: preserve selection, result quality, authority, useful conceptual/retrieval anchors, decision-surface control, proof, discoverability, and deliberate context/representation mechanisms.

## Report

Verify findings against exact-current files/state. Deduplicate by mechanism and rank by user impact, recurrence, safety, stale-risk, and correction cost.

Return:

- inventory/state boundary;
- ownership/composition findings;
- behavioral instruction dispositions;
- residual decision-surface findings;
- capability/reference/script/template/data/asset dispositions;
- structural/resource drift;
- experimental disposition when applicable;
- healthy repetition/deliberate friction retained;
- prioritized actions and rejected recommendations; and
- proof needs/limitations.

“No finding” means no issue found within the declared checks, not that every skill is optimal.
