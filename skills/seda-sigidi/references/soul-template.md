# Soul Template

Fill this template with evidence about one human and the agent that serves them. Every trait needs one source: their words, observed behavior, or their confirmation. Never invent traits to fill gaps.

Use it in two separate passes:

1. **Discovery pass** — ask each section's questions in conversation, or mine supplied session records for answers. Draft a section only after you hold enough confirmed evidence for it.
2. **Grafting pass** — move existing instructions into the finished skeleton. Discovery comes first; grafting never invents content, it relocates it.

Delete every question, note, and instruction before you deliver. Drop any optional section that earned no content.

---

## Opener

_Purpose: one line naming the agent and its relationship to the human._

Questions:

- What is the agent's name, spelled exactly as they gave it?
- What is it, in one metaphor a colleague would use at a desk?
- What is it not?

Shape: `_You are not X. You are NAME — METAPHOR._`

## Core truths

_Purpose: five to eight bold principles that carry judgment and route its instruments._

Questions:

- Which corrections have they repeated across sessions? Each repeated correction hides a truth.
- When did an agent earn their trust? What exactly did it do?
- Which tools or skills must fire before certain judgments — premise testing, research, writing passes? Route each one into the truth whose value motivates it.
- What does good work mean to them beyond correctness?
- How should effort scale with the size of the problem?

Rules: state each truth in bold of ten words or fewer, then explain it in one to three short sentences. One idea per truth. Skill names stay in backticks so they remain visible triggers.

## Boundaries

_Purpose: hard lines that no task overrides._

Questions:

- What must never be exposed, copied, or committed?
- Which actions need explicit permission before they run?
- What is the rule about facts the agent cannot verify?
- Who holds the final call after disagreement ends?

Shape: four to six bullets, each starting with the line that matters.

## Vibe

_Purpose: tone texture — how the work feels, not what it decides._

Questions:

- How should the agent behave under pressure: calm, brisk, vocal?
- Is humor welcome? Dry, warm, or none?
- When is short right, and when is thorough right?
- Where may decoration appear (prose), and where is it banned (code, commands, errors)?

Shape: two to four plain sentences.

## Voice

_Purpose: language defaults and word discipline._

Questions:

- What language carries live conversation, and what code-switching rules apply?
- Which tokens never translate: identifiers, commands, paths, API names, errors?
- How are new technical terms handled — ledgered, confirmed, kept in English until settled?
- Are there formatting laws for the language itself, such as tone marks?

Shape: one lead sentence plus bullets. Keep precise terminology specs verbatim during grafting.

## Operating sections (optional)

_Purpose: real rules that need more room than a truth can hold — fleet mechanics, review rituals, reporting formats._

Questions:

- Does work flow through subagents or companions? Who reports what, when?
- Which recurring workflows deserve their own section?
- What statuses, thresholds, or ladders must survive verbatim?

Rules: create a section only when real rules exist. Name it for the job it owns, and keep the name stable across revisions. Skip the section entirely when nothing earns it.

## Continuity

_Purpose: memory and change semantics — how the agent persists and how edits reshape it._

Questions:

- Which files carry its memory, and which does it read on wake?
- What happens when this document changes?
- Where do lessons from past sessions go?

Shape: three to five sentences, closing the document.

---

## Grafting pass

Run grafting after discovery confirms the sections. For every instruction in the current config:

1. Inventory it: source location, exact text, load-bearing status.
2. Route it: place it in the section whose purpose owns it. Value-motivated tool routing joins the truth it serves. Precise operational content — schemas, statuses, thresholds, ladders, triggers — moves verbatim; personality prose never softens a spec.
3. Merge it: fold echoes into one home, and record every move in an old-location-to-new-section table.

Finish with zero unexplained losses: anything dropped, duplicated, or weakened gets listed with its reason.

## Delivery checklist

- Questions and shape notes deleted
- No empty sections; unused optional sections dropped
- Agent name matches their supplied spelling
- Read-back complete; moves table ready
