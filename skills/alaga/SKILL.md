# Alága

Deliver the requested engineering result in the actual codebase. Keep intake, diagnosis, incident recovery and implementation distinct. Explanation-only requests stop before edits.

## Find the real change

Pin expected/observed behavior, scope, consumers and current evidence. Trace the entry point through its authoritative owner to effects and proof. Search by domain meaning, comparable behavior and actual symbol identity. A spelling match or empty search result is not full coverage; inspect framework registration, generated paths and alternate entry points when material.

For a defect reproduce the original scenario and establish the smallest supported causal mechanism. Compare a supplied repair against that failure and affected controls. Authorized incident mitigation can precede complete diagnosis: verify user-visible recovery, preserve evidence and reconcile uncertain external effects before replay. Recovery does not authorize unrelated permanent work.

Discover established representations before adding parallel ones. Follow a comparable domain value through declaration, conversion, persistence/wire format, lifecycle and consumers. Follow a converter when semantics fit, not merely because it exists. A new enum declaration is not the entire integration. Resolve meaning with [amose](../amose/SKILL.md), intent with [atona](../atona/SKILL.md), and consequential structure with [architect](../architect/SKILL.md).

## Implement the smallest sound solution

Prefer existing language, framework and provider guarantees to custom coordination. Apply DRY to knowledge, YAGNI to speculative capability, and project formatting to the result. Preserve readable control flow, data, compatibility and unrelated work. A consequential deliberate limit needs an observable revisit condition.

For persistence, authorization, migrations, concurrency, external effects or generated/build inputs, read [integration](references/integration.md). For test design, test-suite changes, generated tests or arithmetic, read [proof](references/proof.md). These are conditional expertise, not universal checklists.

Use TDD when it improves discovery or confidence and honor explicit test-first requirements. Red must represent the intended missing behavior/interface, not broken setup, skips or zero selection. Useful regressions remain unless obsolete or genuinely subsumed. Test-after work is not TDD.

Use rerunnable transforms when consistency warrants them. Retain scripts only when reuse or mechanical proof earns maintenance. Architecture cleanup is not a prerequisite for an adequate local repair.

## Establish completion

Exercise the changed contract with the cheapest evidence able to reject a realistic failure. Reuse sufficient checks; add protection for a material gap. Verify checks ran against this candidate. Distinguish pre-existing failures, cached results, skips, setup errors and live acceptance. Inspect the final diff and affected consumers; rerun only invalidated proof.

A compiler guarantee can own one invariant while a runtime path remains unproved. A mock does not establish its real dependency's integration. State limitations instead of weakening acceptance to make the result green.

Use [atunwo](../atunwo/SKILL.md) for requested or useful independent judgment, respecting a request to skip it. Resolve warranted findings. Return behavior, decisive executed evidence and limits. [Seda PR](../seda-pr/SKILL.md) owns authorized commit/push/PR work; delivery alone does not grant it.
