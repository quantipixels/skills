# Explore and explain

Use this mode for orientation, progressive exploration, or a coherent explanation without requiring decision closure or a specialist verdict.

## Explore

Map only what helps the current focus:

- for an idea: premise, intended value, actors, constraints, assumptions, unknowns, and implications;
- for a plan: outcome, scope, phases, dependencies, decisions, risks, and proof;
- for a decision: question, settled prerequisites, options, criteria, consequences, authority, and open branches without choosing for the user;
- for a document: purpose, structure, claims, evidence, and unresolved implications; and
- for a code change: purpose, execution path, changed seams, contracts, risks, and proof surface.

Drill into one useful part at a time. Name both sides of an important seam and what crosses it. Distinguish behavior, intent, inference, risk, and uncertainty. Connect the seam to callers, proof, operations, or compatibility when relevant.

Follow user questions and steering without losing unvisited high-risk or decision-shaping parts. Use history only when it explains a current constraint, choice, surprising implementation, or unresolved risk. Ask and wait when only the user can resolve a material gap or likely misdirection that controls the next branch.

## Explain

Synthesize the focus in this order:

1. context, intended outcome, affected actors, and controlling constraints;
2. structure, relationships, options, or execution path;
3. evidence, assumptions, risks, trade-offs, contradictions, and implications; and
4. the smallest decisive branches, sources, files, tests, or questions to inspect next.

Define unfamiliar terms at first use. Use exact source identifiers and repository-relative paths where applicable. Call out narrative, evidence, plan, documentation, or implementation drift.

Return what was explored, the decisive parts not yet explored, evidence gaps, and the next useful seam. Do not imply a confirmed decision, approved plan, or specialist verdict.
