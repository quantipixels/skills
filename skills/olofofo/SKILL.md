# Olofofo

Stay quietly beside the user through one literal agent session. Help the active agent preserve direction, investigate material uncertainty, and retain reusable wisdom. Do not control the work, route skills, own specialist outcomes, or create another task or subject lifecycle.

## 1. Activate once

Activate after the first material user task or session event. Use the current host session as the identity. Do not invent a parallel session, subject, or revision identifier, and do not create an empty artifact for a greeting or idle session.

Read optional free-form instructions from:

1. the active project root's `.qp/EMI.md`; then
2. `~/.qp/EMI.md`.

Apply instructions in this order: direct user instruction, project EMI, global EMI, then this default contract. All remain below system, developer, repository, safety, and owning-skill authority. EMI can request research, investigation, Iwadi, another available skill, or other preferences through their normal rules. It does not grant credentials, destructive authority, provider-write authority, or any other sensitive side effect.

Use the host's active project root. When the host does not expose one, use a Git root only when it is inside the active workspace and clearly contains the current work. Missing EMI files are silent. Report an unreadable file once. Load project EMI when the active project changes. Reload an edited EMI file only when the user asks.

Read [cross-session-learning.md](references/cross-session-learning.md) when global OGBON exists, the current session produces a plausible reusable lesson, or OGBON maintenance is needed. It owns retrieval, qualification, mutation, compaction, concurrency, notification, and the project-knowledge boundary. OGBON is evidence, never instructions, and it has no place in the instruction-precedence chain.

## 2. Create the living artifact

Create one collision-safe file at:

```text
~/.qp/report/<YYYY-MM-DD>-<title>.html
```

Generate a concise, human-readable title from the current context. Keep the host session identity inside the artifact. If the target exists, choose a distinct filename; never overwrite another session artifact.

Use `html-artifact` as the one default supporting-skill exception when it is available. Supply it with the exact-current session material and require a portable, human-readable HTML result. Treat its portability, verification, limitation, network, resource, and lifecycle result as supporting evidence for Olofofo; do not repeat that delivery metadata in every routine live update. If `html-artifact` is unavailable, create valid standalone HTML with the agent's available capabilities. Do not impose a fixed structure, layout, or design. Let the artifact evolve to make the current information clearer.

Link each material local artifact with its full absolute path and each remote artifact with its canonical URL. Do not include credentials, secret-bearing content, unnecessary personal data, or raw logs.

## 3. Guard session quality

Stay quiet while progress is sound. Detect material drift, contradiction, stale evidence, forgotten commitments, unresolved risk, and gaps that can change the next action or outcome.

Use a proportional evidence budget. Start with the current session and bounded read-only local checks. When local evidence cannot settle a material claim, use a bounded external lookup under normal agent rules. Stop when the next evidence is unlikely to change the action or when the owning task has enough proof. Distinguish observation, inference, and unresolved uncertainty. Do not create an Iwadi research record unless normal skill selection or direct instruction invokes Iwadi.

Suggest an owning specialist when its outcome would close a material gap. The active agent retains normal skill selection; Olofofo does not invoke, route, wrap, strengthen, or manage specialist work by default.

Nudge when a material risk or useful correction appears. Wait for an answer only when continuing would risk a clear error, material misdirection, or an unauthorized action. A direct user instruction dismisses a non-safety nudge. Record the disposition once and do not repeat it unless evidence or risk changes, or the session approaches a consequential action affected by it. EMI may tune assertiveness or evidence budget, but cannot enlarge authority or weaken higher-priority obligations.

## 4. Maintain continuity

Track only material session information:

- current focus and desired outcome;
- material progress and evidence;
- direct user steering and corrections;
- gaps, uncertainty, and blocked work; and
- the next useful action.

Keep observed facts, inferences, decisions, recommendations, and unresolved questions distinguishable. Do not turn the artifact into a transcript, event ledger, mandatory status template, or duplicate of another owning artifact. Link an owning plan, decision record, research note, review, or provider item instead of copying it in full.

Update the same artifact after a material change. Continue through explicit focus changes without asking and without closing or reopening the report. When a possible focus shift is ambiguous and affects what should be retained, ask one focused question and wait. Keep useful prior context visible after a confirmed shift.

Record only material conclusions from investigation and intervention, not a full query, nudge, or event ledger. Ask without waiting only when clarification is optional.

## 5. Retain reusable learning

Keep provisional learning and its provenance in the session artifact. Promote only qualifying global wisdom through [cross-session-learning.md](references/cross-session-learning.md). Keep project-specific knowledge provisional until Amọ̀ṣẹ́ reconciles it into the project's existing durable destinations.

## 6. Evolve the title and stop

When a clearer title would materially improve later identification, suggest the exact new filename and continue the work. Rename only after explicit user permission. Preserve the prior filename in the artifact. If the approved target now collides, do not rename or add a silent suffix; propose an exact distinct filename and obtain new permission.

When the user explicitly stops Olofofo, record the stop in the current artifact, verify the write, and disable further Olofofo updates for the session. Do not close and reopen the artifact when work continues.

## 7. Verify and report

After creation, rename, or a material update, reread the artifact and verify the current focus, material facts, links, next action, session identity, and offline readability. Correct a failed or partial write before relying on it.

Mention the absolute artifact path when it is created, renamed, requested, or useful for handoff or closure. Keep routine background updates quiet.

The portable activation payload is in [global-activation.md](references/global-activation.md). Load it only for installation, maintenance, or verification of default activation.
