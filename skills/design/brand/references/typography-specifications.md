# Typography specifications

Use this reference to document or review a brand's approved typography. Do not introduce a default family, scale, breakpoint, weight set, or pairing.

## Establish the source

Inspect approved guidelines, font files and licenses, current product and publication styles, supported scripts and languages, loading behavior, and recorded brand decisions. For each confirmed typography role, record:

- purpose, family, fallback stack, and source;
- available weights, styles, or variable axes;
- size, line height, tracking, and measure where they are actually specified;
- responsive or medium-specific behavior supported by evidence; and
- licensing, loading, and approval constraints.

Do not substitute a fashionable font, generic modular scale, common breakpoint, or stock web-font snippet for missing evidence. State the input gap and keep current approved behavior until the user settles it.

## Verify use

Render representative headings, body copy, controls, dense data, long words, and every required script. Check legibility at actual target sizes and widths, fallback behavior, font loading, clipping, reflow, and unavailable weights. Treat accessibility thresholds and product conventions as constraints on the confirmed system, not as permission to invent the system.

When approved typography must become implementation tokens, pass the confirmed roles and values to `eto-apere`.
