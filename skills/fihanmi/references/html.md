# Portable HTML and living views

Use the requested destination or existing artifact. For a new standalone report use `.qp/artifacts/<subject>/index.html`; Atọ́nà supplies its plan destination. Maintain one document, stable anchors and explicit revision/status. Independent domain/evidence records are not duplicate plans.

## Preserve meaning

Pin governing question, reader, source/candidate identities, evidence cutoff, accepted decisions and open choices. The source owner decides meaning; presentation cannot invent status, causality, priority, confidence or approval. Incompatible/stale source cuts remain visibly partial.

Keep decision-critical meaning and qualifications visible; a pointer alone is insufficient when omission changes a decision. Put background one action away and raw logs at their actual source. Add a compact machine-readable context capsule for identity, current state, blockers/next action and high-value locators. Exclude full records, secrets and machine-local paths.

## Build for use

Use semantic HTML, ordered headings and landmarks. Let the subject determine the representation: interface, transition, comparison, evidence table or sequence. Use meaningful color with labels/shapes for monochrome legibility. Preserve units, baselines and uncertainty; confidence, readiness, verdict and completion are distinct.

Support narrow widths, inspectable tables, keyboard controls, visible focus and reduced motion. Keep controlling qualifications outside disclosure. Interactions may expose supplied meaning or collect clearly unaccepted feedback. Static pages are the default.

Escape supplied content. Add no unrequested analytics, credentials, remote requests or executable source markup. Prefer self-contained delivery. Necessary renderers require explicit dependency, trust, data and failure boundaries with readable fallback. Do not build a reusable frontend framework for a document.

For living updates lead with material changes and consequences while retaining new-reader context. Update the same plan before dependent decisions. Distinguish observed, illustrative and proposed states; animations are not execution evidence.

## Verify and deliver

Check source identity, critical coverage, opening/status, navigation, provenance, contrast, non-color cues, dependencies and fallback. Use one bounded render smoke when static readability is uncertain. For interactions exercise the material control and relevant keyboard/narrow-width behavior, not a combinatorial matrix.

Return exact locator, revision, delivery shape, runtime code/data, evidence access and limits. Source inspection proves fidelity, render inspection supports layout, and observed reader use supports comprehension. Never claim unperformed accessibility, host or reader validation. Recheck only invalidated claims.
