# AOT processing and native images

**Priority:** MEDIUM  
**Rules:** 5

Treat AOT/native support as a separate runtime contract with explicit dynamic-feature hints and proof.

Apply only the rules whose trigger exists in the candidate. Preserve the detected Spring Boot, Spring Framework, Java, Jakarta, servlet/reactive, database, security, and deployment contracts.

Examples are illustrative; preserve the repository baseline, imports, build system, framework generation, public API, and operational constraints.

<a id="aot-stabilize-jvm-behavior-first"></a>
## `aot-stabilize-jvm-behavior-first` — Prove JVM behavior before optimizing for native

> Keep one accepted application contract and add AOT/native packaging only when its startup, memory, distribution, or platform benefit is required.

### Why it matters

Debugging application defects and native-reachability defects simultaneously increases uncertainty.

### Avoid

Do not rewrite architecture solely to satisfy native image before the normal JVM path is correct.

### Prefer

Run ordinary tests first, then AOT/native build and runtime tests against the same acceptance paths.

### Nuance

Some workloads are better served by JVM CDS/AOT cache or tuned JVM images; compare measured operational goals.

- **Spring Boot native images:** <https://docs.spring.io/spring-boot/reference/packaging/native-image/index.html>
- **Spring Framework AOT:** <https://docs.spring.io/spring-framework/reference/core/aot.html>

<a id="aot-register-narrow-runtime-hints"></a>
## `aot-register-narrow-runtime-hints` — Register the minimum reflection, resource, proxy, and serialization hints

> Closed-world compilation must know dynamic access paths that the JVM discovers at runtime.

### Why it matters

Missing hints fail only in native execution; blanket reachability metadata increases image size and hides unsupported design.

### Avoid

Do not register whole packages for reflection or mark every member invocable.

### Prefer

Use `RuntimeHintsRegistrar`, supported annotations, and tracing-agent output as evidence; scope hints to the actual dynamic contract.

### Nuance

Framework-managed components often receive generated hints automatically; add custom hints only for application/library dynamics.

### Example

**Avoid**

```java
hints.reflection().registerType(
    DynamicPlugin.class,
    MemberCategory.values()
);
```

**Prefer**

```java
hints.reflection().registerType(
    InvoiceProjection.class,
    MemberCategory.INVOKE_DECLARED_CONSTRUCTORS
);
```

- **Spring Framework AOT:** <https://docs.spring.io/spring-framework/reference/core/aot.html>
- **RuntimeHints API:** <https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/aot/hint/RuntimeHints.html>

<a id="aot-avoid-unbounded-runtime-discovery"></a>
## `aot-avoid-unbounded-runtime-discovery` — Avoid dynamic discovery that cannot be closed at build time

> Runtime classpath scanning, generated bytecode, late proxy interfaces, scripts, and arbitrary reflection may not be visible to native analysis.

### Why it matters

The JVM can discover them lazily while a native image cannot include unknown future code.

### Avoid

Do not assume a JVM plugin mechanism or reflection-heavy serializer automatically works in native mode.

### Prefer

Use explicit registrations, build-time code generation, supported service loading, or keep that subsystem on the JVM.

### Nuance

A plugin product with unknown third-party extensions may be fundamentally incompatible with one closed native image.

### Sources

- **Spring Framework AOT:** <https://docs.spring.io/spring-framework/reference/core/aot.html>
- **GraalVM reachability metadata:** <https://www.graalvm.org/latest/reference-manual/native-image/metadata/>

<a id="aot-separate-buildtime-runtime-config"></a>
## `aot-separate-buildtime-runtime-config` — Know what AOT captures at build time

> Bean definitions, conditions, proxies, and generated code can be derived during AOT processing while environment values remain runtime inputs only where supported.

### Why it matters

Changing a property after image build may not alter structure that was fixed during AOT.

### Avoid

Do not assume every conditional bean/configuration choice remains runtime-dynamic in a native image.

### Prefer

Identify build-time conditions and produce separate images or explicit runtime strategy when structural variation is required.

### Nuance

Secrets and environment-specific values must remain external even when configuration metadata is processed at build time.

### Sources

- **Spring Framework AOT:** <https://docs.spring.io/spring-framework/reference/core/aot.html>
- **Spring Boot native images:** <https://docs.spring.io/spring-boot/reference/packaging/native-image/index.html>

<a id="aot-run-native-specific-proof"></a>
## `aot-run-native-specific-proof` — Exercise the actual native executable or container

> Compilation success does not prove reflection, resources, proxies, TLS, time zones, charsets, logging, or shutdown at runtime.

### Why it matters

Native-only failures commonly appear outside ordinary JVM tests.

### Avoid

Do not claim native support from `process-aot` or metadata generation alone.

### Prefer

Run native tests/smoke acceptance, start the packaged image, call critical endpoints/jobs, and verify observability and shutdown.

### Nuance

Keep the proof proportional; one critical path per dynamic subsystem is more useful than duplicating every unit test.
