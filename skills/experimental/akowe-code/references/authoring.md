# Authoring and maintenance

Use this only when changing Akọ̀wé Code itself.

## Keep the result small

Akọ̀wé Code owns one task-scoped Code Craft Brief. A new ecosystem does not automatically deserve a public skill. Add or expand an internal pack when repeated tasks need the same durable mechanism and bounded retrieval remains clear.

Retain a principle only when it is:

- reusable across a meaningful range of code in that ecosystem;
- materially non-obvious or recurrent in agent output;
- tied to a credible correctness, lifecycle, compatibility, performance, security, or code-craft consequence;
- scoped by material exceptions/version boundaries;
- not better owned by a deterministic formatter/linter/static rule;
- original synthesis with primary-source attribution.

## Promotion path

```text
one task finding
→ task-local brief only

repeated repository-specific finding
→ ayewo evidence
→ amose local-craft record when authorized

repeated cross-project durable finding
→ ayewo evidence
→ ko-skill change to the compact pack

reliable mechanical pattern
→ irinse / project-native deterministic tool
```

Never auto-mine runtime sessions into shared guidance.

## Freshness

For each ecosystem pack, keep a research cutoff and controlling first-party source family in `source-map.md`. Recheck version-sensitive claims when a task falls outside that boundary. Do not bump pack prose merely because a patch release exists unless behavior, compatibility, defaults, security, or expert guidance materially changed.

## Proof

Before publishing a pack change, verify:

- stack detection selects it only when relevant;
- a mixed-stack task composes only controlling packs;
- an unknown/newer stack falls through to bounded research rather than guessing;
- the Code Craft Brief remains bounded and candidate-specific;
- safe counterexamples prevent universal style rules;
- stable implementation/review owners remain complete without this Experimental skill;
- manifest/router/README/metadata remain explicit-only and coherent.
