# Build evidence

Use when a dependency, build-performance, cache or generated-input question depends on build-tool state that manifests and a successful build do not expose. `architect` owns structural choice, `adanwo` owns comparative measurement, `alaga` owns fixes and `atunwo` owns independent findings. Return evidence to that owner rather than making its judgment here.

Pin the project, wrapper/toolchain, selected target, profile or configuration, relevant environment and requested build entry point. Reuse project-native reports. A remote scan or uploaded log requires existing authority for its destination and disclosed data.

Inspect the resolved graph for the actual build scope. Record selected versions, variants, features or scopes, substitutions and replacements, active profiles, and the path or reason that selected a disputed node. A declaration is not the resolved graph: Gradle resolves configurations and variants; Maven's effective POM incorporates inheritance and active profiles while its dependency tree supplies transitives; Cargo metadata exposes its resolve graph; Go computes a build list and can apply workspace replacements. Distinguish presence in a whole graph from use by the selected target or runtime.

Preserve relevant action outcomes for compilation, generation, packaging and tests: executed, skipped or no-source, up-to-date, and restored or replayed from cache. A successful cached test result is prior evidence for its cache key, not a fresh execution. Force a fresh run only when the question requires it and current authority permits the effect.

For latency, use dependency-aware critical-path evidence rather than adding parallel task durations. Preserve concurrency and identify the chain gating completion; also account for configuration or startup, waiting, resource contention and cache transfer when they affect elapsed time. Give comparative performance claims to `adanwo`.

When incremental correctness controls the question, vary one authorized representative input, including generator schema, template, configuration, tool version or environment where relevant. Verify correct recomputation or valid retrieval for the new input and downstream consumption of the resulting output. Physical rerun and changed output are not universal requirements: a valid new-input cache entry may be reused, and different inputs can legitimately produce identical output. Then make no change and confirm justified reuse. A clean build proves clean construction, not complete invalidation inputs. Missing inputs, outputs or producer-consumer edges can yield a fast stale build.

Restore only owned probe changes. Return the pinned scope and relevant selection, action, timing or invalidation evidence with its locator and material gaps.
