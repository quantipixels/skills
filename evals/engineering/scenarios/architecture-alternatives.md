# Actor task: architecture alternatives

Resolve the supplied consequential design choice against the current project and one frozen requirement. Compare extending the present owner, simplifying its structure and using the supplied established library alternative. Recover relevant rationale from code and available history, and state when an alternative is unsuitable rather than implementing it merely to fill a comparison.

Use bounded disposable spikes only where execution can settle a material uncertainty. Keep the same behavioral contract and evidence burden across viable alternatives. Compare integration and migration work, operational consequences, maintenance ownership and the experience of actual consumers and contributors. Agent convenience cannot justify degrading those outcomes. Respect the supplied installation and file scope; no production migration is authorized by this evaluation task.

Return the recommendation with decisive evidence, spike diffs where applicable, rejected alternatives and their reasons, and unresolved facts that could change the choice. Neither fewer lines nor a new dependency is inherently an improvement. Preserve the viable current design when the alternative has not earned its change cost.
