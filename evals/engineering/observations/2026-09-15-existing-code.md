# Existing-code delivery screening

Two fresh subagent coding attempts used the revised Alága in the native collaboration host. They received the task, source fixture and skill path, without the external acceptance oracle or suggested implementation. Workers had assignment-only filesystem separation, not an enforced sandbox. Exact runtime model, token cost and call counts were not exposed in the recorded results. No control arm was run. These results establish successful examples, not a causal improvement or general reliability.

Returned source and tests are preserved in the adjacent `2026-09-15-reuse.patch` and `2026-09-15-settlement.patch`, relative to each original fixture. Apply to disposable copies, never the fixture originals. Re-run `python3 -m unittest discover -v` there and invoke the repository's `oracle.py <copy> <case>` separately. The worker narratives were checked against source and executed outcomes; self-reported passing tests alone were not accepted as proof.

The original reuse fixture fails acceptance with missing-action errors. Mechanical oracle checks distinguish that state from a working minimal integration and reject a no-op pause and bypassed domain guard. The fixture is an additive-feature screen, so it is not inserted into the paired repair profile that specifically requires assertion-based red proof. No test-runner semantics were loosened to count it as a successful paired repair.

Independent instruction audit identified two delivery-path gaps: runtime/configuration registration can hide consumers from static caller searches, and changes to buffering/parallelism can pass small functional tests while exceeding operational limits. The integration reference now exposes those concerns without a mandatory survey or benchmark. Existing architecture, stateful-proof and review methods were retained rather than copied into new skills.

Remaining evidence gaps: framework-interception failure, mixed-version rollout, resource exhaustion and zero-test false-success behavior have explicit guidance but were not exercised by these coding trials. The senior-engineer stance was changed together with the instructions; its independent effect is unmeasured. Follow-up trials should target these boundaries before stronger reliability claims.
