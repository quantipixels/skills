# Existing-code practices in peer repositories

Compared actual instructions with QP's delivery changes. These are methodological comparisons, not executed demonstrations that another library performs better.

| Source | Useful practice | QP decision |
| --- | --- | --- |
| [Compound Engineering implementation loop](https://github.com/EveryInc/compound-engineering-plugin/blob/0ec66db4e9f7391c6df9e363b65c664265ccd538/skills/ce-work/references/implementation-loop.md) | Discover existing tests before choosing proof; recognize already-shipped work; trace callbacks, alternate interfaces and interacting error strategies. | Existing Alága discovery and proof selection cover most of this. Added the concrete risk of stacked retries, exception translation and fallback duplication. Avoid fixed two-level tracing and mandatory duplicate test categories. |
| [pstack how](https://github.com/cursor/plugins/blob/c1c0a32802223f4be824112dd83d33ad29a8b26c/pstack/skills/how/SKILL.md) and [domain modeling](https://github.com/cursor/plugins/blob/c1c0a32802223f4be824112dd83d33ad29a8b26c/pstack/skills/principle-model-the-domain/SKILL.md) | Build an actionable subsystem model: triggers, data flow, decisions, locations and gotchas. Prefer structures that own real domain rules. | Retain scoped behavior tracing and semantic reuse. Do not import mandatory explainer/explorer dispatch or redesign an adequate existing representation merely because a new requirement appears. |
| [Superpowers planning](https://github.com/obra/superpowers/blob/b36e0829c6d0140e93cfef2ca599b1b07d4a7797/skills/writing-plans/SKILL.md) | Map file responsibilities and consumed/produced interfaces before implementation; follow existing layout. | Keep owner/consumer discovery in direct delivery, so it also works without a planning workflow. Do not require a detailed task document for every change or optimize file size in isolation. |
| [Trail of Bits context building](https://github.com/trailofbits/skills/blob/027bc47a69a276c340717bafdc3708263094b9a4/plugins/audit-context-building/skills/audit-context-building/SKILL.md) | Follow callees to determine which assumptions are actually enforced; retain unresolved assumptions instead of claiming understanding. | Added a concise dependency-precondition check. Keep the audit-specific per-function dossiers and compulsory subagents out of ordinary implementation. |

The useful common ground is specific evidence about the existing system, not stronger adjectives such as “meticulous.” QP keeps those obligations with Alága, independent judgment with Àtúnwò, and consequential structure with Architect. No new skills, dependency installation, model roster or mandatory CI gate was added.
