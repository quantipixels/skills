# Published-tag migration checks — 2026-09-25

These checks used the actual `v4.2.0` Git tag (the published release has no separate assets) and the `feat/alarina-single-entry` candidate at `942407d8`. Each manager ran with a disposable home; the personal installations were untouched. The tag contains 19 discoverable QP skills and root-level Codex and Claude plugin manifests. Its manifests have no version field, so Codex reported the old installation as `local` and Claude reported it as `unknown`, rather than `4.2.0`.

The earlier [local fixture check](2026-09-25-local-native.md) also verified package-file fidelity, unrelated-plugin preservation and scoped uninstall registration for both native managers. A separate fresh Codex session in the user's normal profile implicitly selected `qp-skills:alarina` for a repository-exploration request and reported the `4.3.0` plugin-cache skill path. That is runtime selection evidence for this request, not proof of every command or of reloading an already-running session.

The actual tag also exposed `codex-orchestra`, which the previous migration guide omitted from its retired-name list. The guide now includes that historical ID and maps every retired entry to its Alárinà command or coordination method.

No test above demonstrates a Git-backed old-to-new transition on one moving ref, mid-copy interruption recovery, automatic deletion of Claude cache files, or live activation in an existing conversation. The migration procedure treats registered plugin state, installed file contents and running-session instructions as distinct evidence, and directs users to inspect state and retry through the manager after an ambiguous update.
