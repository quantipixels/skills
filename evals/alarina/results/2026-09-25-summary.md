The source now has one discoverable skill, 39 focused commands, and 16 engineering playbooks. All 18 former specialist and utility skill roots are retired. ## What was adopted from Impeccable

The comparison used Impeccable revision `edb9c7fbcba158fb6236bd043d6cba18d9cde8d3`:

- [The source entrypoint](https://github.com/pbakaus/impeccable/blob/edb9c7fbcba158fb6236bd043d6cba18d9cde8d3/skill/SKILL.src.md) provides one public entry with a broad trigger description, a command table and exact method references. Alárinà uses that shape with engineering methods; the references contain the methods themselves.
- [Routing guidance](https://github.com/pbakaus/impeccable/blob/edb9c7fbcba158fb6236bd043d6cba18d9cde8d3/skill/reference/routing.md) separates bare invocation, selection advice and execution. Alárinà preserves those distinctions and uses existing project context for optional menu suggestions.
- [Provider transforms](https://github.com/pbakaus/impeccable/blob/edb9c7fbcba158fb6236bd043d6cba18d9cde8d3/scripts/lib/utils.js) and [plugin path handling](https://github.com/pbakaus/impeccable/blob/edb9c7fbcba158fb6236bd043d6cba18d9cde8d3/scripts/lib/plugin-paths.js) establish that invocation prefixes and installed resource paths belong to the distribution surface. Alárinà compiles provider-qualified invocation metadata and Claude's agent dependency from portable source; internal links resolve from their containing installed file.
- [Behavioral evaluation guidance](https://github.com/pbakaus/impeccable/blob/edb9c7fbcba158fb6236bd043d6cba18d9cde8d3/tests/skill-behavior/README.md) distinguishes routing checkpoints from completed workflows and retains failed or incomplete evidence. This report uses the same separation.

The design engine, visual quality rules, project signals executable, hooks, shortcut pinning and design records were not copied. Alárinà remains an engineering operating entrypoint. Its agent profile runs the same skill within the assigned scope rather than introducing another workflow.

## Remaining evidence limits

The clean-profile Codex model execution failed authentication with HTTP 401 despite an existing user-profile login. No credentials were extracted or copied to the test profile. The `ccx` direct and agent-mode probes establish explicit method loading, but native implicit selection, competitive selection and broad task completion remain unverified. Native manager acceptance and supplied-entry tests cannot stand in for those observations.

Codex and Claude are the two compiled native providers. The other 18 registry entries are experimental promotion candidates, not verified releases. Native Codex plugin-agent support is not claimed; use Alárinà in the main agent or a bounded worker assignment.

This evaluation does not establish improvement over direct specialist invocation, all engineering workflows end to end, behavior across models, Git-backed marketplace refresh, same-version refresh or interrupted-update recovery. Explicit qualified entry is the documented fallback when implicit selection misses.
